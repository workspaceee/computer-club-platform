# C4.4 — карточка игры: состояние на конец чата

Задача: обложка, категория, рейтинг, сколько играет в клубе **сейчас**, лейбл
лаунчера (Steam / Epic / Riot / Battle.net / …). Чат остановлен **в середине
рефакторинга** — код в дереве компилируется как две параллельные реализации
карточки, и это первое, что нужно закрыть.

## 0. Главное: ничего не удалено, но новая карточка ещё не подключена

В `components/launcher/games-view.tsx` сейчас живут **две** карточки:

1. старая — встроенная в файл функция `GameCard` (строки ~565–692) вместе со
   старой `Highlight` (переименованной в мёртвую `RemovedHighlight`, строки
   ~518–563, нигде не вызывается);
2. новая — `components/launcher/game-card.tsx`, экспортирует `GameCard`,
   написана полностью, но **`games-view.tsx` её не импортирует** — сетка
   (строка ~470) вызывает старую, локальную функцию.

Из-за этого `game.launcher` и `game.players` сейчас читаются в двух местах с
разными (уже несовместимыми) допущениями — см. §2.

## 1. Что сделано

- **`lib/types/catalog.ts`** — `Game.launcher` был `string`, стал типизированным
  `GameLauncher` (union из 14 значений лаунчеров, ровно тех, что есть в
  `lib/mock/db.ts`). `Game.players` документирован как *lifetime*-счётчик
  каталога, явно не «сейчас в клубе».
- **`lib/types/social.ts`** — новый тип `GamePresence = Record<ID, number>`,
  разреженная карта «сколько сидит за столом в этой игре прямо сейчас».
- **`lib/mock/db.ts`** — `getGamePresence()`: считает по `db.players`, только
  тех, у кого есть `machineId` (сидит в клубе) и `playingGameId`. Импортирован
  `GameLauncher`, тип семян каталога и `HOUSE_ACCOUNT_LAUNCHERS` типизированы
  этим union.
- **`lib/mock/api/social.ts`** — `fetchGamePresence()`, обёртка
  `query('social.fetchGamePresence', () => getGamePresence())` над
  `getGamePresence()`. Импорты `getGamePresence` и `GamePresence` добавлены.
- **`lib/game-labels.ts`** (новый) — вынесенный `GAME_CATEGORIES` /
  `CATEGORY_KEYS`, чтобы карточка и `games-view.tsx` не дублировали список
  жанров.
- **`components/launcher/game-card.tsx`** (новый, готов) — карточка на
  `Game + playersInClub: number + query: string`:
  - жанр — залитый бейдж (`CATEGORY_KEYS`);
  - лаунчер — **обособленный бейдж с рамкой** рядом с жанром, печатает
    `game.launcher` как есть (без перевода — имена продуктов, F2.2), `title`
    содержит слово «Launcher»/ключ `games.launcherLabel` + само имя;
  - рейтинг — через `formatNumber` (не `toFixed`, чтобы разделитель был
    локальным), плюс `sr-only` фраза `games.ratingOutOf`;
  - счётчик «сейчас в клубе» — **точка + число, только когда `playersInClub >
    0`**, без анимации (без пульса — правило T3), `sr-only` фраза через
    `tp('games.inClubNow', n, { n })`;
  - подсветка поиска (`Highlight`) перенесена внутрь этого файла.

## 2. Что не сделано — и это то, из-за чего оценка «выполнено» невозможна

### 2.1 Подключить новую карточку (обязательно, без этого пункт C4.4 не закрыт)

В `components/launcher/games-view.tsx`:

1. Импортировать `GameCard` из `@/components/launcher/game-card` и удалить
   старую встроенную `function GameCard(...)` (строки ~565–692).
2. Удалить мёртвую `function RemovedHighlight(...)` (строки ~518–563) — она не
   вызывается ничем, это хвост рефакторинга.
3. Удалить `CATEGORY_KEYS`/`CATEGORIES`, объявленные прямо в `games-view.tsx`
   (строки ~34–55), и брать их из `lib/game-labels.ts` (`GAME_CATEGORIES`,
   `CATEGORY_KEYS`) — иначе это снова два списка одних и тех же восьми жанров.
4. В месте вызова (строка ~470) передавать пропы новой карточки:
   `<GameCard key={game.id} game={game} playersInClub={presence[game.id] ?? 0} query={rawQuery} />`.

### 2.2 Заменить симуляцию «игроков» на серверный презенс (обязательно)

Сейчас в `games-view.tsx` живёт ровно то, от чего написана карточка должна
избавить продукт:

- `useState<Record<string, number>>({})` — сид из `game.players` (lifetime-счётчик
  каталога, тысячи) при первом ответе `fetchGames`;
- `setInterval(..., 5000)` — блуждание `±10` каждые 5 секунд;
- сортировка `sort === 'online'` берёт значение из этого же блуждающего стейта.

Всё это нужно снести и заменить на реальный презенс:

```tsx
const presence = useApi(
  ['gamePresence'],
  () => fetchGamePresence(),
  { refreshInterval: CLUB_NOW_REFRESH_MS }, // тот же интервал, что у club-now-card.tsx (§2.4)
)
```

и передавать `presence.data?.[game.id] ?? 0` в карточку. Сортировку `online`
после этого нужно пересчитывать по `presence.data`, а не по локальному стейту
— т.е. вариант `SORT_PARAM.online` (сейчас алиас на `'popular'`, с комментарием
«сортировка ещё клиентская») можно либо оставить как есть (сортировка по
презенсу — клиентская операция над уже полученной страницей, это легально по
той же причине, что и локальный поиск в C4.3), либо явно сортировать
`filtered` по `presence.data` в `useMemo`. Выбрать один вариант и убрать
комментарий, который теперь будет врать про причину.

### 2.3 Экспортировать `fetchGamePresence` из барреля

`fetchGames` в `games-view.tsx` импортируется из `'@/lib/mock/api'`
(баррель), а не из `'@/lib/mock/api/social'` напрямую. Проверить, что
`fetchGamePresence` реэкспортирован из `lib/mock/api/index.ts` (или как он
называется у барреля — см. `lib/mock/api.ts`/`lib/mock/api/index.ts`, в этом
чате баррель не был прочитан до конца) вместе с типом `GamePresence`, иначе
импорт в `games-view.tsx` придётся тянуть из `social.ts` напрямую, что
нарушает принятый в файле стиль импорта.

### 2.4 Инвалидация/интервал презенса — сверить с `club-now-card.tsx`

`components/launcher/club-now-card.tsx` уже решает ровно эту задачу для другой
карточки (сколько друзей в клубе сейчас) — там есть готовый
`CLUB_NOW_REFRESH_MS` и, вероятно, обработка события старта/завершения игры
через `lib/realtime/events.ts`. Presence на карточке игры должен обновляться
по той же дисциплине (интервал + при необходимости socket-событие
старта/завершения сессии), а не жить с собственным магическим числом. Прочитать
`club-now-card.tsx` целиком и повторить его паттерн инвалидации для
`fetchGamePresence`.

### 2.5 Именной конфликт `GameLauncher`

В `lib/agent/bridge.ts` уже существует **другой** тип с тем же именем:

```ts
export type GameLauncher = 'steam' | 'epic' | 'riot' | 'battlenet' | 'ea' | 'ubisoft' | 'standalone'
```

— это id лаунчера для агента станции (нижний регистр, урезанный набор), не
пересекается с новым `GameLauncher` из `lib/types/catalog.ts` (отображаемые
строки, полный набор из 14). Компилируется без ошибок, потому что модули не
импортируют друг друга напрямую, но одно и то же имя с разным смыслом в одном
проекте — заминка для следующего чтения. `lib/agent/mock-agent.ts` уже держит
`LAUNCHER_MAP: Record<string, GameLauncher>` (агентский смысл) со значениями
`Steam → steam`, `Battle.net → battlenet` и т.д. — ключи там совпадают со
значениями каталожного union, это не баг, но переименовать один из двух типов
до финальной проверки (предлагаю `lib/agent/bridge.ts` → `AgentLauncherId`,
он моложе и локальнее по использованию).

### 2.6 Словарные ключи (i18n) — отсутствуют во всех трёх языках

`game-card.tsx` уже ссылается на ключи, которых нет в словарях:

- `games.launcherLabel` — подпись «Launcher»/«Лаунчер»/… для `title`-атрибута
  бейджа;
- `games.ratingOutOf` — `sr-only` фраза с параметром `{v}` («Rating 4.8 out of
  5» / «Рейтинг 4,8 из 5» / …);
- `games.inClubNow` — плюрализуемая (`tp`, как `games.libraryCount`) фраза
  «сейчас в клубе N человек» с параметром `{n}`.

Добавить во все три файла — `lib/i18n/dictionaries/en.ts`, `ru.ts`, `lt.ts` —
рядом с существующими `games.*` ключами (там же, где `libraryCount`, см. `en.ts:1301`,
`ru.ts:839`, `lt.ts:788`). `Dictionary` типизирован по `en.ts` (см.
`lib/i18n/types.ts`), поэтому пропуск ключа в `ru.ts`/`lt.ts` — это ошибка
компиляции, а не рантайм-фолбэк на английский; `npx tsc --noEmit` сам укажет,
где не хватает.

### 2.7 `game.rating.toFixed(1)` в старой карточке — не переносить

Старая встроенная карточка форматирует рейтинг через `toFixed(1)` — это ровно
тот баг с разделителем-точкой на русском/литовском экране, который
`game-card.tsx` уже чинит через `formatNumber`. Убедиться, что после удаления
старой карточки (§2.1) `toFixed` не остаётся ни в одном месте, где рейтинг
всё ещё печатается напрямую (проверить detail-панель C4.5, если она к этому
моменту уже существует).
