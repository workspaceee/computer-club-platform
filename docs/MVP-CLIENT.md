> Цель: зафиксировать **что именно получает клиент компьютерного клуба**, как он взаимодействует с админом, и как это реально реализовать.

## 1. Резюме

Мы делаем не «биллинг с лаунчером» (как ggLeap / Senet), а **игровую платформу клуба**, где клиент —
главный герой: у него есть аккаунт, прогресс, друзья, задания и причина возвращаться именно в наш клуб.

Три клиентские поверхности:

| Поверхность | Где | Что делает |
|---|---|---|
| **Launcher (Client PC)** | ПК в клубе, Windows, полноэкранный shell | Логин, сессия, игры, бар, прогресс, помощь |
| **Companion (Mobile/Web PWA)** | Телефон клиента | Бронь, пополнение, баланс, заказ в бар, турниры, друзья, статистика |
| **Kiosk (self-service)** | Планшет/ПК на входе | Регистрация нового клиента, чек-ин по QR, покупка времени без админа |

Админ-панель — отдельный продукт, но **в этом MVP описан каждый контракт админ ↔ клиент** (раздел 6),
потому что без него клиентский функционал не работает.

**Принцип MVP:** всё, что помечено `P0`, обязательно к запуску. `P1` — сразу после. `P2` — задел, не блокирует.

## 2. Чем мы должны быть лучше конкурентов

| Возможность | ggLeap | Senet | **IMBA (мы)** |
|---|---|---|---|
| Лаунчер на ПК | есть, тяжёлый, устаревший UI | есть | Быстрый, анимированный, gamepad/клавиатура-навигация, тёмная тема |
| Мобильное приложение | ограниченно | есть | PWA-first: бронь, кошелёк, заказ в бар, друзья, турниры |
| Программа лояльности | очки + призы | бонусы | Уровни + XP + **сезонный Battle Pass** + ежедневные квесты + челленджи |
| Заказ бара с ПК | нет / внешне | частично | Полноценный магазин с корзиной, **статусом заказа в реальном времени** |
| Социальное | нет | нет | Друзья, «кто сейчас в клубе», party-приглашение на соседний ПК, лобби |
| Турниры | базово | базово | Регистрация, чек-ин, сетка, автоуведомления «твой матч через 5 мин» |
| Связь с админом | звонок/крик | тикет | **Кнопка помощи с типом проблемы + чат + видит статус** |
| Продление времени | у админа | у админа | Сам продлевает в 2 тапа, оплата с кошелька/картой |
| House-аккаунты игр | есть | есть | Есть + авто-логин + предупреждение «аккаунт занят» + cloud-save sync |
| Прозрачность | слабая | слабая | История сессий, чеки, куда ушли деньги и минуты |

Ключевые дифференциаторы, которые надо не потерять: **скорость UI, реальное время, лояльность-как-игра, мобильный companion.**

## 3. Роли

| Роль | Описание |
|---|---|
| `guest` | Не зарегистрирован. Может смотреть цены/бронь, играть только через гостевой пропуск, выданный админом |
| `member` | Зарегистрированный клиент: кошелёк, прогресс, друзья, история |
| `staff` (админ/оператор) | Управляет сессиями, ПК, заказами, тикетами, время/скидки |
| `manager` | + тарифы, товары, турниры, отчёты, модерация |

MVP-ограничение: без сложных прав. `staff` vs `manager` — один флаг.

## 4. Ключевые пользовательские сценарии (happy paths)

### 4.1 Новый клиент пришёл в клуб `P0`
1. Админ (или киоск) заводит клиента: телефон → SMS/или сразу ник+PIN.
2. Клиент получает **личный QR-код** в PWA (и на почту/в SMS ссылку).
3. Админ назначает ПК → на ПК появляется «Ожидание входа: Пётр, место A-07».
4. Клиент садится, сканирует QR / вводит ник+PIN → сессия стартовала, таймер пошёл.
5. Onboarding-оверлей на 15 секунд: «Твоё время», «Заказ в бар», «Кнопка помощи», «Coins».

### 4.2 Постоянный клиент, самообслуживание `P0`
1. В PWA: бронирует место на 19:00, оплачивает 3 часа с кошелька.
2. Приходит, на входе киоск: скан QR → «Место B-03 разблокировано, беги».
3. На ПК автологин по QR → сессия начата, время списывается.

### 4.3 Заказ в бар с игрового ПК `P0`
1. Клиент открывает Shop → добавляет Monster + чипсы → Checkout.
2. Оплата: кошелёк / coins / «оплачу на кассе».
3. Заказ уходит админу. Клиент видит статус: `Принят → Готовится → Несём (2 мин) → Доставлен`.
4. Пуш-баннер на ПК: «Заказ у тебя на столе». Coins +X за покупку.

### 4.4 Время кончается `P0`
- `-15 мин`: мягкий тост + «Продлить».
- `-5 мин`: заметный баннер, звук, «Продлить 1ч за 120 ₴ / 1200 coins».
- `0`: экран блокировки с сохранением состояния (игра не убивается сразу — grace 60 сек на сохранение).
- Продление в 2 тапа → таймер продолжается, ничего не закрывается.

### 4.5 Проблема с ПК `P0`
1. Клиент жмёт `F1` / кнопку «Помощь» → выбирает тип: «Мышь/клавиатура», «Звук», «Игра не запускается», «Другое» + текст.
2. Тикет мгновенно у админа с номером места.
3. Клиент видит: «Админ принял · идёт к тебе», может дописать в чат.
4. Закрытие тикета → «Проблема решена?» 👍/👎.

### 4.6 Играем с друзьями `P1`
1. Клиент видит «В клубе сейчас: 4 друга» + их места.
2. Создаёт Party → приглашает → друг видит инвайт на своём ПК → принимает.
3. Party-чат + «играем в CS2» → у всех в лаунчере кнопка «Запустить с party».

## 6. Контракт админ ↔ клиент (матрица событий)

Каждое действие админа обязано **мгновенно** отразиться на клиенте (WS/SSE, < 1 сек).

| Действие админа | Что происходит у клиента | Приоритет |
|---|---|---|
| Назначить ПК клиенту | На экране блокировки: «Ожидаем: Пётр» → вход упрощён | `P0` |
| Старт сессии | Лаунчер открывается, таймер идёт | `P0` |
| Добавить время / продлить | Таймер пересчитывается + тост «+1 час от админа» | `P0` |
| Списать/скорректировать время | Тост с причиной, история фиксирует кто и почему | `P0` |
| Пополнить кошелёк | Баланс обновляется + тост + запись в транзакциях | `P0` |
| Пауза / возобновление | Экран блокировки / возврат в лаунчер | `P0` |
| Завершить сессию | Grace 60 сек → сохранение → экран «Спасибо» + итоги визита + NPS | `P0` |
| Перенос на другой ПК | Модалка «Перейди на B-05», сессия переносится | `P1` |
| Смена статуса заказа | Обновление статуса заказа в реальном времени | `P0` |
| Позиция в стоп-лист | Товар становится недоступен, из корзины убирается | `P0` |
| Принять тикет / ответить | Статус тикета + сообщение в чате | `P0` |
| Broadcast | Тост или модалка (по важности) | `P0` |
| Варнинг / бан | Модалка с обязательным подтверждением; бан → логаут | `P1` |
| Заблокировать/разблокировать игру | Игра скрыта или помечена «недоступна» | `P1` |
| Открыть турнир / вызвать на матч | Афиша + напоминание | `P1` |
| Выдать промо/подарок | Тост «Админ подарил тебе 1 час» + confetti | `P1` |

Обратный поток (клиент → админ): запрос помощи, заказ, запрос продления, запрос пересадки,
жалоба, NPS, «клиент отошёл (пауза)».

## 7. Техническая реализация

### 7.1 Компоненты системы
```
┌────────────────────┐    HTTPS/WS   ┌──────────────────────┐
│  Launcher (Client) │◄─────────────►│                      │
│  Next.js в kiosk-  │               │   IMBA Cloud          │
│  окне Electron/WV  │               │   Next.js 16 (App)    │
└─────────┬──────────┘               │   + Neon Postgres     │
          │ local IPC                │   + Drizzle ORM       │
┌─────────▼──────────┐               │   + Better Auth       │
│  Agent (Windows)   │◄─────────────►│   + Realtime (SSE/WS) │
│  запуск игр, локи, │               │                      │
│  очистка профиля   │               └──────────┬───────────┘
└────────────────────┘                          │
┌────────────────────┐                          │
│ Companion PWA      │◄─────────────────────────┤
│ Admin Panel        │◄─────────────────────────┘
└────────────────────┘
```

- **Launcher** — текущий Next.js-проект. Работает как shell: полный экран, без выхода в Windows.
- **Agent** — тонкий локальный сервис (Node/Go) на ПК: запуск процессов, блокировка клавиш,
  очистка пользовательского профиля, отчёт «жив ли ПК». Без него нельзя реально запускать игры.
- **Cloud** — единый API + realtime, источник правды по времени и деньгам.
- **Anti-cheat времени:** таймер считается **на сервере**, клиент только отображает.
  Клиент дергает `heartbeat` каждые 10 сек, сервер декрементирует. Обрыв сети > 60 сек → агент блокирует ПК.

## 9. Нефункциональные требования

- **Скорость:** любой переход < 150 мс, старт лаунчера < 3 сек, LCP < 1.5 с.
- **Реальное время:** событие админа → клиент < 1 сек.
- **Отказоустойчивость:** нет интернета → лаунчер работает в degraded-режиме (таймер локально + сверка после),
  заказы и покупки блокируются с понятным сообщением.
- **Безопасность:** PIN — bcrypt/argon2; QR-токены одноразовые с TTL; rate-limit на вход;
  секреты house-аккаунтов не отдаются в браузер в открытом виде (агент подставляет).
- **Аудит:** каждое действие staff над клиентом — с автором и причиной, клиент видит в истории.
- **Доступность:** полная навигация с клавиатуры (клуб = мышь+клава), фокус-стили, контраст AA, `prefers-reduced-motion`.
- **Локализация:** UA / RU / EN, единый файл словаря.
- **Возраст:** отметка «до 18» → ограничение по времени и игр 18+ (законодательство/комендантский час).

## 10. Edge cases (обязательно обработать)

1. Клиент вышел, не закрыв сессию → авто-пауза при idle 10 мин, затем уведомление админу.
2. Время кончилось во время рейтингового матча → grace 60 сек + один раз «доиграть 5 мин в долг» (лимит).
3. Два клиента хотят один house-аккаунт → блокировка + «свободен через ~X мин» + альтернатива.
4. Оплата прошла, интернет упал → идемпотентность + повторная сверка, ничего не теряется.
5. ПК зависает/ребут → сессия восстанавливается по heartbeat, время не сгорает.
6. Заказ отменён/нет товара → авто-возврат средств + уведомление.
7. Админ завершил сессию по ошибке → «отменить завершение» в течение 60 сек.
8. Гостевой пропуск закончился → предложение зарегистрироваться и сохранить прогресс.
9. Клиент забыл PIN → вход по коду через админа, без блокировки визита.
10. Двойной вход одного аккаунта на 2 ПК → запрет + «ты уже в сессии на A-07».
