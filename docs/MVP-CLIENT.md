## 1. Резюме

Мы делаем не «биллинг с лаунчером» (как ggLeap / Senet), а **игровую платформу клуба**, где клиент —
главный герой: у него есть аккаунт, прогресс, друзья, задания и причина возвращаться именно сюда.

Три клиентские поверхности:

| Поверхность | Где | Что делает |
|---|---|---|
| **Launcher (Client PC)** | ПК в клубе, Windows, полноэкранный shell | Логин, сессия, игры, бар, прогресс, настройки ПК, помощь |
| **Companion (Mobile PWA)** | Телефон клиента | Баланс, пассы, бронь, заказ в бар, турниры, друзья, статистика |
| **Kiosk (self-service)** | Планшет/ПК на входе | Регистрация, чек-ин по QR, покупка пасса без админа |

Админ-панель — отдельный продукт, но **в этом документе описан каждый контракт админ ↔ клиент** (раздел 7),
плюс полный список того, что админ конфигурирует (раздел 6), потому что без этого клиент не работает.

**Приоритеты:** `P0` — обязательно к запуску, `P0.5` — сразу за ядром (Battle Pass), `P1` — следующий релиз, `P2` — задел.

## 3. Роли и модели биллинга

### 3.1 Роли
| Роль | Описание |
|---|---|
| `guest` | Без регистрации. Играет по времени, выданному админом. **PostPaid** — платит на кассе в конце |
| `member` | Зарегистрирован: кошелёк, пассы, прогресс, друзья, история |
| `staff` | Управляет сессиями, ПК, заказами, тикетами, выдаёт время, закрывает счета |
| `manager` | + тарифы, пассы, товары, Battle Pass, турниры, отчёты |

### 3.2 Две модели оплаты (ключевое изменение v0.2)

**PostPaid (гость и «открытый счёт»)** `P0`
```
Админ: «выдать время» → выбирает ПК (любой) + минуты (или пасс)
   ↓
Открывается tab (счёт): время идёт, всё, что клиент заказывает (бар, продление), пишется в tab
   ↓
Клиент видит на ПК: «Время: 2:14 · К оплате: € 9.50»  ← полная прозрачность
   ↓
Сессия закончилась → админ закрывает tab на кассе → «Оплачено»
```
- Гость всегда видит **текущую сумму к оплате** — это честно и снимает конфликты.
- Клиент может добавить заказ в бар в tab (если админ разрешил в настройках).
- Кнопка «Создать аккаунт и сохранить время» доступна на любом экране гостя.

**PrePaid (member)** `P0`
```
Клиент покупает пасс (касса / PWA / киоск) → минуты на аккаунте → тратятся при игре
```
- Остаток минут не сгорает (если в пассе не задан `expires_at`).
- Кошелёк EUR используется для бара и продления.

> Один и тот же клиент может быть в PrePaid и добрать в PostPaid, когда минуты кончились (если `allow_debt = true`).

## 4. Система пассов `P0`

Пасс — товар, который админ создаёт в панели. Клиент видит его в лаунчере, PWA и на киоске.

### 4.1 Модель пасса (всё поля настраиваются админом)
| Поле | Пример | Комментарий |
|---|---|---|
| `name` | «5 часов VIP» | отображается клиенту |
| `hours` | 5 | базовое время |
| `bonus_minutes` | +30 | **бонусное время** — то, что вы просили |
| `price_cents` | 1500 (€ 15.00) | EUR |
| `zone_scope` | `vip` / `standard` / `ps5` / `any` | класс зала |
| `time_window` | `any` / `night 22:00–08:00` / `happy 12:00–16:00` | ночной пасс = окно + опц. безлимит |
| `unlimited_in_window` | true (для ночного) | безлимит внутри окна вместо минут |
| `valid_days` | 30 | срок жизни неиспользованных минут (0 = бессрочно) |
| `coins_reward` | 100 | сколько coins даёт покупка |
| `visible_to` | `all` / `members` / `level ≥ N` | эксклюзивные пассы для лояльных |
| `active` | true | вкл/выкл без удаления |

### 4.2 Стартовый набор (пример, редактируется в админке)
| Пасс | Время | Бонус | Зона | Окно |
|---|---|---|---|---|
| 3 часа | 3 ч | — | Обычный зал | любое |
| 5 часов | 5 ч | +30 мин | Обычный зал | любое |
| 10 часов | 10 ч | +2 ч | Обычный зал | любое |
| Ночной | безлимит | — | Обычный зал | 22:00 – 08:00 |
| 3 часа VIP | 3 ч | — | VIP | любое |
| 5 часов VIP | 5 ч | +30 мин | VIP | любое |
| Ночной VIP | безлимит | — | VIP | 22:00 – 08:00 |
| PS5 · 2 часа | 2 ч | — | PS5 | любое |

### 4.3 Как клиент видит пассы
- Карточка пасса: время **крупно**, бонус — зелёным бейджем `+30 мин бонус`, цена, зона, окно действия.
- Расчёт выгоды: `€ 3.00 / час` — подсказка «выгоднее на 25 %» у лучшего пасса.
- Если пасс не подходит текущей зоне — карточка неактивна с пояснением «только для VIP».
- Ночной пасс подсвечивается автоматически с 21:00 («до старта окна 1 ч»).
- Покупка: «Оплатить на кассе» (создаёт запрос админу) · «Оплатить картой» `В разработке` · «Списать с кошелька».

### 5.4 Настройки ПК (переработано в v0.2) `P0`

Экран «Настройки ПК» — сетка иконок-плиток. Часть открывает **нативные панели Windows/NVIDIA** через агента,
часть управляется прямо в лаунчере.

| Плитка | Действие | Реализация |
|---|---|---|
| **Графика (NVIDIA)** | Открывает NVIDIA Control Panel | агент: `nvcplui.exe` / `control.exe desk.cpl` fallback |
| **Мышь** | Открывает настройки мыши Windows | агент: `ms-settings:mousetouchpad` / `main.cpl` |
| **Звук** | Открывает настройки звука (ввод/вывод) | агент: `ms-settings:sound` / `mmsys.cpl` |
| **Наушники / микрофон** | Быстрый выбор устройства ввода-вывода + тест микрофона | агент читает список устройств, лаунчер показывает список |
| **Яркость** | Слайдер **в лаунчере** (как сейчас) | остаётся как есть |
| **Разрешение** | Список **реальных доступных разрешений ПК** (подтягивается от NVIDIA/Windows) | агент: `EnumDisplaySettings` → список, применение с подтверждением |
| **Частота обновления** | Список Hz для выбранного разрешения | агент, вместе с разрешением |
| **Клавиатура** | Настройки клавиатуры Windows | агент: `ms-settings:easeofaccess-keyboard` / `control keyboard` |
| **Счётчик FPS** | Переключатель оверлея FPS в играх + его настройки (см. 5.4.1) | настройка в лаунчере, рендер — агент `P0` |
| **Периферия (мышь клуба)** | DPI-профиль, если мышь поддерживает | `P2` |
| **Интерфейс лаунчера** | Язык, «меньше анимаций», размер шрифта | в лаунчере |

**Правила UX для этого экрана:**
- Плитки, требующие агента, до его появления показывают состояние `Требует агент клуба` — не молчаливое ничего.
- Применение разрешения: подтверждение «Оставить эти настройки?» с авто-откатом через 15 сек (как в Windows).
- Все изменения — **только для текущей сессии**; при логауте агент возвращает дефолт клуба.
  Исключение — настройки счётчика FPS: они привязаны к игроку и переносятся на любой ПК клуба.
- Ничего опасного: доступ к панелям через whitelist агента, не к произвольному `exec`.

#### 5.4.1 Счётчик FPS (оверлей в игре) `P0` — функция для клиентов

> Игрок включает один раз — работает во всех играх. У ggLeap/Senet этого нет: сильное преимущество для тех, кто следит за производительностью.

| # | Функция | Приоритет |
|---|---|---|
| F1 | Переключатель «Счётчик FPS»: вкл / выкл. Хранится за игроком, а не за ПК | `P0` |
| F2 | Угол экрана: верх-лево / верх-право / низ-лево / низ-право (по умолчанию верх-лево) | `P0` |
| F3 | Режим: **компактный** (только FPS) / **расширенный** (FPS, 1 % low, GPU %, CPU %, температура GPU, ping, VRAM) | `P0` |
| F4 | Внешний вид: размер S/M/L, прозрачность фона, цветовая индикация по порогам клуба (зелёный / жёлтый / красный) | `P0` |
| F5 | Живой предпросмотр в настройках: пример кадра с реальными значениями телеметрии | `P0` |
| F6 | Честные состояния: «Оверлей недоступен на этом ПК» (старый агент / exclusive fullscreen), «Отключено администратором» | `P0` |
| F7 | Контракт агента: `setOverlay(config)`, `getOverlayCapabilities()`; в моках — только предпросмотр | `P0` |

**Правила:** оверлей никогда не перекрывает игровой прицел и интерфейс — фиксированные углы, без произвольного перетаскивания;
глобальный запрет админом выключает переключатель с явной причиной; пороги цветов приходят из настроек клуба, не из кода.

## 8. Ключевые сценарии

### 8.1 Гость пришёл и сел куда захотел (главный сценарий, free seating) `P0`
1. Клиент садится за свободный ПК. На экране: «Свободен · назови номер места администратору: **A-07**».
2. Админ в панели: «Выдать время» → ПК A-07 → 2 часа (или пасс) → Подтвердить.
3. На ПК мгновенно: «Время выдано · 2:00» → лаунчер открыт, таймер идёт.
4. В топбаре: `2:00` и `К оплате € 6.00` (растёт при заказах).
5. Внизу постоянный призыв: **«Создать аккаунт и сохранить время»**.
6. Время кончилось → grace 60 сек → «Подойди на кассу · к оплате € 9.50».
7. Админ закрывает счёт → «Оплачено, спасибо» + предложение аккаунта с сохранением статистики визита.

### 8.2 Гость становится участником `P0`
1. Жмёт «Создать аккаунт и сохранить время».
2. E-mail → код из письма (6 цифр) → ник → PIN.
3. Всё время визита, покупки и статистика **переносятся на аккаунт**, coins начисляются задним числом.
4. Первое достижение «Добро пожаловать в клуб» + бонус (настраивается).

### 8.3 Постоянный клиент покупает пасс `P0`
1. Открывает Shop → Пассы → «10 часов +2 ч бонус · € 25.00 · Обычный зал».
2. «Оплатить на кассе» → админ видит запрос → подтверждает оплату.
3. Минуты на аккаунте, coins начислены, тост с бонусом.

### 8.4 Заказ в бар `P0`
Каталог → корзина → оплата (кошелёк / в счёт / на кассе) → статус `Принят → Готовится → Несём → Доставлен` в реальном времени → coins.

### 8.5 Время кончается `P0`
`-15 мин` тост → `-5 мин` баннер + звук → `0` grace 60 сек → «Продлить» / «Доиграть в долг (лимит из админки)» / экран блокировки.

### 8.6 Настройка ПК `P0`
Клиент → Настройки ПК → «Графика» открывает NVIDIA Control Panel поверх лаунчера; «Мышь» и «Звук» — панели Windows;
яркость и разрешение — прямо в лаунчере (список разрешений реальный, от ПК).

### 8.7 Проблема с ПК `P0`
`F1` → тип проблемы + текст → тикет админу с номером места → «Админ идёт к тебе» → чат → закрытие + 👍/👎.

**Инварианты (деньги и время):**
- Любое изменение времени/денег — **только транзакцией** с записью в `transactions`. Никогда «просто UPDATE».
- `tabs.total_cents` = сумма `tab_items` (пересчёт в транзакции, не доверяем клиенту).
- Клиентские мутации (продление, заказ, покупка пасса) — с `Idempotency-Key`.
- Все запросы клиента фильтруются по `user_id`/`guest_id` из сессии (в Neon нет RLS).
- Все суммы — целые центы EUR, никаких float.

## 11. Нефункциональные требования

- **Скорость:** переход < 150 мс, старт лаунчера < 3 сек.
- **Реальное время:** событие админа → клиент < 1 сек.
- **Оффлайн:** нет интернета → degraded-режим (локальный таймер + сверка после), покупки блокируются с понятным сообщением.
- **Безопасность:** PIN — argon2; QR/коды одноразовые с TTL; rate-limit на OTP и вход;
  секреты house-аккаунтов не попадают в браузер (подставляет агент); панели ПК — whitelist, не произвольный exec.
- **Аудит:** каждое действие staff — с автором и причиной (`audit_log`), клиент видит в своей истории.
- **Доступность:** полная навигация с клавиатуры, фокус-стили, контраст AA, `prefers-reduced-motion`.
- **Локализация:** EN по умолчанию, словарь готов к добавлению языков.
- **Возраст:** отметка «до 18» → ограничение игр 18+ и комендантский час (настраивается).

## 12. Edge cases

1. Гость ушёл не заплатив → tab остаётся `open`, админ видит долг по месту, ПК помечен.
2. Клиент вышел, не закрыв сессию → авто-пауза при idle, уведомление админу.
3. Время кончилось в рейтинге → grace 60 сек + «доиграть в долг» в пределах лимита.
4. Два клиента на один house-аккаунт → блокировка + «освободится ~через X мин» + альтернатива.
5. Оплата на кассе прошла, интернет упал → идемпотентность, сверка, ничего не теряется.
6. ПК ребутнулся → сессия восстанавливается по heartbeat, время не сгорает, tab жив.
7. Заказ отменён → авто-возврат (кошелёк) или снятие позиции из tab + уведомление.
8. Админ завершил сессию по ошибке → «отменить завершение» в течение 60 сек.
9. Гость сел за ПК, который забронирован на 19:00 → предупреждение админу и на ПК заранее.
10. Применили неподдерживаемое разрешение → авто-откат через 15 сек.
11. Двойной вход одного аккаунта на 2 ПК → запрет + «ты уже в сессии на A-07».
12. Пасс не подходит зоне (купил «Обычный», сел в VIP) → предложение доплаты разницы, без блокировки.

## 13. План реализации

### Фаза 0 — Прототип (текущий этап, без агента)
Есть: логин ✅, home, games, shop, profile, таймер, корзина, настройки, лог-экран ✅.
**Добираем:** Guest/PostPaid режим с «к оплате», вкладка Пассы, переработанные Настройки ПК,
Help/тикеты, Session End + итоги, квесты на Home, Battle Pass, Wallet/Tab, предупреждения о времени.

### Фаза 1 — Реальный бэкенд `P0`
Neon + Drizzle + Better Auth (email OTP); серверный таймер и heartbeat; пассы и минуты;
tabs и транзакции; заказы; тикеты; SSE; конфиг-слой `settings`; админ-панель (сессии, выдача времени, кассa, заказы, тикеты).

### Фаза 2 — Лояльность и мобайл
Battle Pass (сезоны, награды), квесты, призы, лидерборды; Companion PWA (баланс, пассы, заказ, QR-вход, занятость клуба).

### Фаза 3 — Windows-агент
Запуск игр, house-аккаунты, панели NVIDIA/Windows, разрешения и аудио, лок Windows, очистка профиля, in-game overlay.

### Фаза 4 — Рост
Бронирование, турниры, друзья/party, онлайн-оплата картой, рефералка, cloud-saves.
