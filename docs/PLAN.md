## 0. Как пользоваться планом

### 0.1 Легенда статусов

Ставьте символ прямо в чекбоксе:

| Метка | Значение |
|---|---|
| `- [ ]` | Не начато |
| `- [~]` | В работе |
| `- [x]` | Готово (принято) |
| `- [!]` | Заблокировано / нужен ответ владельца |
| `- [-]` | Отменено / вынесено из скоупа |

### 0.2 Правила работы

1. **Один этап за раз.** Не начинаем Этап 2, пока Этап 1 не закрыт по Definition of Done.
2. **Этап 0 обязателен.** Без дизайн-системы и мок-слоя каждый экран будет «своим» — это главная причина, почему ggLeap/Senet выглядят собранными из кусков.
3. **Каждая задача = отдельный файл или изолированный набор.** Никаких «page.tsx на 1500 строк».
4. **Дизайн-эталон — экран лога** (`components/lock-screen.tsx`). Любой новый экран проходит проверку из §0.4.
5. **Каждая задача заканчивается проверкой в браузере** (скриншот + прогон сценария), а не «код компилируется».
6. **Данные — только через мок-API.** Ни один компонент не хардкодит цифры. Это условие безболезненного перехода на Neon в Этапе 4.
7. **Каждый текст — через i18n.** Ни одной строки прямо в JSX (EN / RU / LT).
8. **Правки в MVP-документ вносим сразу**, как только решение меняется. План и MVP не должны расходиться.
9. **Граница доверия.** Этапы 0–3 работают на моках, где клиент сам считает время и деньги. Это допустимо только для демо. Каждая задача, которая создаёт или меняет деньги/минуты, помечается в коде комментарием `// TRUST: сервер обязан пересчитать (Этап 4)`. Этап 4 не считается закрытым, пока все такие метки не сняты. Без этого правила в биллинге останется дыра.

### 0.3 Definition of Done для любой задачи

- [ ] Функция работает по сценарию из MVP-документа (happy path + минимум 2 edge case)
- [ ] Все состояния нарисованы: `loading` / `empty` / `error` / `success` / `disabled`
- [ ] Тексты вынесены в i18n, переведены на EN + RU + LT
- [ ] Числа/деньги/время идут из мок-API и форматируются через `lib/format.ts` (EUR, `HH:MM:SS`)
- [ ] Соответствие дизайн-чеклисту §0.4
- [ ] Работает клавиатурой, есть фокус-стили, ARIA-роли, `sr-only` где нужно
- [ ] Проверено в браузере на 1920×1080 и 1366×768 (реальные разрешения клубных ПК)
- [ ] Нет ошибок в консоли, нет отладочных `console.log`

### 0.4 Дизайн-чеклист (эталон = экран лога)

- [ ] Фон: `app-ambient` + `hairline-grid`, панели `glass` / `glass-strong`
- [ ] Цвета только из токенов: `background`, `surface`, `panel`, `border`, `primary #e5352b`, `success`, `warning`, `danger`, `info`, `text-high/medium/low`. **Никаких прямых `bg-white`, `text-black`, фиолетового**
- [ ] Шрифты: `font-display` (Manrope) для заголовков, `font-sans` (Inter) для текста, `font-clock` для таймеров/цифр, `label-mono` для микро-лейблов с трекингом
- [ ] Радиусы: `radius-sm/md/lg/xl` (3/6/10/16px) — тактическая геометрия, не «пузыри»
- [ ] Заголовки: `uppercase`, `tracking-tight`, `text-balance`, акцент словом в `text-primary` с `text-glow`
- [ ] Каждый раздел имеет нумерованный `SectionHeader` в стиле `01 / SESSION`
- [ ] Анимации: `framer-motion`, вход `opacity+y`, `duration 0.25–0.7`, `ease-out`, `layoutId` для пиллов
- [ ] Все анимации отключаются флагом «Уменьшить анимации» и `prefers-reduced-motion`
- [ ] Layout: flexbox по умолчанию, grid только для 2D-сеток, `gap-*` вместо margin-хаков
- [ ] Иконки только `lucide-react`, размеры 16/20/24. **Никаких эмодзи**

## 1. Карта этапов

| Этап | Название | Результат | Зависит от |
|---|---|---|---|
| **0** | Фундамент | Дизайн-система, мок-бэкенд, i18n, шина событий, AgentBridge | — |
| **1** | Клиент (member) | Полный лаунчер зарегистрированного игрока, все функции и дизайн | 0 |
| **2** | Гостевой режим | PostPaid: выдача времени админом, открытый счёт, оплата на кассе | 1 |
| **3** | Админ-панель | Полная админка со всеми функциями, управляющая Этапами 1–2 | 1, 2 |
| **4** | Реальный бэкенд | Neon + Drizzle + Better Auth, SSE, замена моков | 3 |
| **5** | Windows-агент | Реальная блокировка ПК, запуск игр, нативные панели настроек | 4 |

> Этапы 4–5 в этом плане описаны верхнеуровнево — детализируем их отдельным документом, когда закроем Этап 3.

# ЭТАП 2 — Гостевой режим (PostPaid)

**Модель (зафиксирована):** гость не платит вперёд. Админ выдаёт время на любой ПК → открывается счёт (`tab`) → гость видит текущую сумму к оплате в реальном времени → оплата на кассе при уходе.

## G1. Вход гостя

- [ ] **G1.1** Вкладка «Гость» на экране лога активируется: «Играй сейчас — платишь при уходе»
- [ ] **G1.2** Сценарий А (основной): админ выдал время на этот ПК → экран автоматически показывает «Время выдано, нажми чтобы начать»
- [ ] **G1.3** Сценарий Б: гость сам нажал «Играть как гость» → создаётся запрос админу, экран ожидания «Админ подтверждает…» с таймером и отменой
- [ ] **G1.4** Минимальная анкета гостя: имя/ник (обязательно), телефон (опционально, для связи). Никакой регистрации
- [ ] **G1.5** Согласие с правилами клуба и с условием оплаты при уходе — обязательный чекбокс
- [ ] **G1.6** Ограничение по возрасту: пометка «18+ зона» там, где настроено админкой
- [ ] **G1.7** Гость видит номер своего ПК и зону крупно (чтобы назвать на кассе)

## G2. Открытый счёт (tab)

- [ ] **G2.1** Постоянно видимая плашка «К оплате: € X.XX» в топбаре гостя — главный элемент интерфейса
- [ ] **G2.2** Экран «Мой счёт»: построчно — игровое время (тариф × минуты), позиции бара, скидки, итог
- [ ] **G2.3** Живой пересчёт стоимости времени каждую минуту, с явным указанием текущего тарифа зоны
- [ ] **G2.4** Тариф зависит от зоны и времени суток (день/вечер/ночь) — при переходе в другой тарифный период счёт показывает это отдельной строкой
- [ ] **G2.5** Пороги счёта: настраиваемый лимит (например € 20) → предупреждение гостю и сигнал админу
- [ ] **G2.6** Заказы в баре добавляются в счёт без предоплаты, с мгновенным обновлением суммы
- [ ] **G2.7** Админ добавил/снял позицию или скидку (`tab.updated`) → гость видит изменение сразу, с тостом «Админ применил скидку 10%»
- [ ] **G2.8** Экран «Как платить»: «Подойди к администратору и назови номер ПК», QR-код счёта для быстрого поиска админом
- [ ] **G2.9** Закрытие счёта админом → гость видит «Счёт оплачен, спасибо» и итоговый чек
- [ ] **G2.10** Незакрытый счёт при уходе → фиксируется долг; если гость привяжет аккаунт, долг переезжает в аккаунт

## G3. Гостевые пассы и время

- [ ] **G3.1** Админ может выдать гостю **пасс** (3 ч / 5 ч / 10 ч / ночной) — тогда счёт содержит фиксированную стоимость пасса вместо поминутного тарифа
- [ ] **G3.2** Гость видит, что у него пасс: «Ночной пасс · осталось 5 ч 12 мин · +60 мин бонус»
- [ ] **G3.3** Бонусные минуты пасса отображаются отдельной строкой и явно помечены как бесплатные
- [ ] **G3.4** Пасс закончился → переход на поминутный PostPaid с явным предупреждением **до** перехода, с кнопками «Продолжить платно» / «Завершить»
- [ ] **G3.5** Пасс ограничен зоной: попытка использовать в другой зоне → понятное объяснение и предложение доплаты
- [ ] **G3.6** Ночной пасс: показ окна действия («до 08:00»), предупреждение при подходе к границе окна

## G4. Функционал гостя

- [ ] **G4.1** Игры: полная библиотека и запуск (без «своих» игровых аккаунтов, house-аккаунты доступны)
- [ ] **G4.2** Бар: полный каталог, заказ в счёт
- [ ] **G4.3** Настройки ПК: полный доступ (яркость, разрешение, нативные панели) — гость должен иметь комфорт не хуже member
- [ ] **G4.4** Помощь и чат с админом: полный доступ
- [ ] **G4.5** Недоступно гостю (с мягким объяснением и кнопкой «Создать аккаунт»): кошелёк, лояльность/квесты/Battle Pass, друзья/пати, турниры, бронирование, история
- [ ] **G4.6** Промо-блок конверсии: «Создай аккаунт — получи 30 минут бесплатно и начни копить награды». Показывается в спокойные моменты, не блокирует игру
- [ ] **G4.7** Апгрейд гостя в member **без потери сессии**: анкета в модале → сессия, счёт и потраченное время переезжают в новый аккаунт, XP начисляется за уже отыгранное
- [ ] **G4.8** Пересадка гостя админом на другой ПК: счёт продолжается, тариф пересчитывается по новой зоне

## G5. Приёмка Этапа 2

- [ ] **G5.1** Прогон: админ выдаёт время → гость играет → заказывает бар → счёт растёт → админ применяет скидку → закрытие счёта
- [ ] **G5.2** Прогон с пассом: выдача, расход, окончание, переход на поминутный тариф
- [ ] **G5.3** Прогон апгрейда в member посреди сессии, проверка переноса счёта и времени
- [ ] **G5.4** Проверка, что гостевой интерфейс визуально идентичен member-интерфейсу (только с меньшим набором разделов) — никакой «урезанной второсортной версии»

# ЭТАП 6 — Companion PWA (отложено, скоуп зафиксирован)

> В MVP-документе телефон был отдельной поверхностью. В плане 1.0 этого блока не было — скрытый скоуп. Фиксирую его здесь как **отложенный**, чтобы он не всплыл посреди Этапа 1.

- [-] **P1.1** Бронирование с телефона (вне клуба)
- [-] **P1.2** Просмотр баланса, пассов и истории
- [-] **P1.3** Заказ в бар с телефона, пока играешь
- [-] **P1.4** Push-уведомления: заказ готов, начинается турнир, напоминание о брони
- [-] **P1.5** QR для входа на ПК с телефона
- [-] **P1.6** Battle Pass и квесты вне клуба (удержание между визитами)

**Условие включения в работу:** только после приёмки Этапа 3. Клиентские экраны Этапа 1 делаем адаптивными (`C2.9`), поэтому PWA будет переиспользовать компоненты, а не переписывать их.

## Приложение 1 — Что решено и не обсуждается заново

| Решение | Значение |
|---|---|
| Валюта | EUR, суммы в целых центах |
| Язык по умолчанию | EN, плюс RU и LT |
| Гостевая модель | PostPaid — играет сейчас, платит при уходе |
| Выдача времени | Админ выдаёт на любой ПК |
| Посадка | Free seating основной сценарий, бронь вспомогательный |
| Пассы | 3 ч / 5 ч / 10 ч / ночной + настраиваемые бонусные минуты |
| Карта клуба | Экран «В разработке», работаем списком ПК |
| Настройки ПК | Нативные панели Windows/NVIDIA; яркость и разрешение в лаунчере |
| Приоритет №1 | Battle Pass / лояльность |
| Конфигурация | Всё настраивается в админке, ничего не хардкодим |
| Клуб | Один клуб, но модель данных готова к сети |
| Агент | Реальный агент — Этап 5, до него мок с честными состояниями |
