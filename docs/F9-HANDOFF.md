# F9 — состояние блока

## 0. Главное: 36 «нарушений» были не недоделкой, а регрессией

Предыдущая передача описывала F9.1–F9.3 как «ещё не сделано». Это было
неверным диагнозом. Код F9 существовал и был доведён — его **снёс коммит**
`2618a23 «feat: remove KitMaterials component and update footer reference»`.

Что этот коммит на самом деле сделал (`git show --stat 2618a23`):

| Файл | Дельта |
|---|---|
| `app/globals.css` | −346 строк: все семь утилит вейлов (`--veil-ink`, `--veil-ink-deep`, `--veil-base`, `--veil-floor{,-deep}`), вся шкала глубины (`--well`, `--scrim`, `--pill{,-deep}`, `.well{,-shallow,-deep}`, `.scrim`, `.pill{,-deep}`) и тир T2 (`.neon-ring-static` / `.neon-edge-static`) |
| 18 файлов `app/`, `components/` | откат на pre-F9 литералы: инлайновые градиенты, `bg-black/NN`, T1 вместо T2 |
| `app/dev/kit/page.tsx`, `kit-data.tsx` | раздел «Материалы» (F9.6) отключён, `kit-materials.tsx` остался в дереве без вызова |
| `public/f9-freeze.js` | +102 строки — харнесс заморозки |

То есть в коммит попал **временный `git checkout <pre-F9-sha> -- app components
lib hooks`**, сделанный для съёмки кадров «до», а не отдельная правка витрины.
Отсюда и ровно те 36 проблем `design:verify`: это исходный pre-F9 срез, а
`F9.1`–`F9.4` в `PLAN.md` были помечены `[x]` честно.

Вывод, который стоит запомнить: откат для съёмки «до» нельзя делать в рабочем
дереве, из которого потом коммитят. Кадры «до» снимаются из `git worktree` на
отдельном каталоге, либо `git stash` восстанавливается **до** коммита.

## 1. Что сделано в этом чате

Работа F9 **восстановлена, а не переписана заново**:

```
git checkout a65367f -- app components lib hooks
```

`a65367f` — состояние ровно перед регрессией (merge PR #135). Между `2618a23`
и `HEAD` в этих каталогах не было ни одной осмысленной правки
(`git diff --stat 2618a23 HEAD -- app components lib hooks` пуст), поэтому
восстановление ничего не затирает: единственное, что появилось позже, — этот
документ.

Важное следствие: восстановленный код **побайтово тот самый**, который в F9.2
сверялся через `getComputedStyle` по всем семи слоям и отснимался на 1920×1080
и 1366×768. Переписывать вейлы «один-в-один» руками не пришлось, и риск
разъехаться на альфе исчез вместе с этим.

`public/f9-freeze.js` не тронут — он лежит в `public/` и в откат не попадал.

## 3. Что осталось

1. **Попиксельное сравнение pre-F9 → HEAD** (приёмка блока, §F9). Харнесс
   готов: `public/f9-freeze.js` через `eval`, `wait 4000` после `networkidle`
   для логина, `wait 32000 && wait 3500` для простоя (порог idle 30 с в
   `hooks/use-idle.ts`), вьюпорты 1920×1080 и 1366×768. Кадры «до» снимать из
   отдельного `git worktree` на pre-F9 SHA — **не** через `checkout` в рабочем
   дереве (см. §0). Перед сравнением версий обязателен замер шума «twin» —
   два кадра одного состояния; дельта значима только заметно выше него.
   Ожидаемая дельта: ноль в пределах шума **везде, кроме** результата F9.4 —
   бегущий сегмент неона остался только у единственного действия экрана
   (карточка доступа на логине, пилюля «разбудить» в простое), пять чипов
   телеметрии, бейдж станции и промо-панель светятся замороженной кромкой T2
   или не светятся вовсе (T3). Это единственное сознательное визуальное
   изменение блока.
2. **Судьба `public/f9-freeze.js`** — оставить рядом с `public/__f9` как часть
   харнесса или удалить после закрытия F9.
3. **Коммит восстановления** — с формулировкой, которая называет причину
   («revert accidental pre-F9 rollback committed in 2618a23»), иначе следующий
   читатель истории решит, что F9 делали дважды.
