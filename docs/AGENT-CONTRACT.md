## 1. Что такое агент и чего он не делает

Агент — служба Windows на игровом ПК. Единственный клиент агента — лаунчер, открытый на этом же ПК.

**Агент отвечает за:** блокировку Windows, запуск и остановку игр, режимы экрана, яркость, профили драйвера, открытие нативных панелей, телеметрию, перезагрузку.

**Агент НЕ отвечает за:** деньги, минуты, сессии, права игрока. Ни одна цифра баланса или остатка времени не приходит из агента и не пересчитывается им. Агент — исполнитель, решение всегда принимает сервер.

Отсюда два жёстких правила:

1. **Агент никогда не разблокирует ПК по своей инициативе.** Разблокировка — только по команде, подписанной сервером (§7).
2. **Агент никогда не возвращает «успех», если действие не выполнено.** Ложный успех хуже отказа: лаунчер обязан показать «Недоступно на этом ПК» (F5.4), а не сделать вид, что кнопка сработала.

## 2. Транспорт

| Параметр | Значение |
|---|---|
| Протокол | WebSocket `ws://127.0.0.1:8787` (JSON-RPC 2.0), запросы и push в одном соединении |
| Привязка | **только** loopback. Внешний интерфейс не слушаем |
| Аутентификация | одноразовый токен машины в `Authorization` при апгрейде; токен пишется установщиком в `%PROGRAMDATA%\IMBA\agent.token` и читается лаунчером |
| Origin | принимаем только `Origin` лаунчера; остальные — `403` |
| Таймаут запроса | 10 с по умолчанию, `launchGame` — до 180 с (прогресс идёт push-кадрами) |
| Версионирование | `getInfo().version` — semver; лаунчер отказывает мажорной версии, которую не знает |

Одно соединение = одна станция. Второе соединение вытесняет первое (защита от двух открытых лаунчеров, `C1.12`).

### Формат кадров

```jsonc
// запрос
{ "jsonrpc": "2.0", "id": "42", "method": "launchGame", "params": { "gameId": "cs2" } }
// ответ
{ "jsonrpc": "2.0", "id": "42", "result": { "launchId": "l-1", "gameId": "cs2", "pid": 8123, "startedAt": "2026-07-26T18:20:11Z" } }
// ошибка — code всегда из §8
{ "jsonrpc": "2.0", "id": "42", "error": { "code": "gameNotInstalled", "detail": "cs2" } }
// push (без id)
{ "jsonrpc": "2.0", "method": "launch.progress", "params": { "launchId": "l-1", "gameId": "cs2", "phase": "launching", "percent": 84, "step": "startingGame" } }
```

`detail` — только для логов и админки. Игроку показывается текст из словарей по `code`, агент **не** присылает прозу и не присылает переводы.

## 3. Методы

Полные сигнатуры — в `AgentBridge`. Здесь то, что не выводится из типов.

### 3.1 Рукопожатие

| Метод | Требование |
|---|---|
| `isAvailable()` | Отвечает быстрее 300 мс. Не выполняет тяжёлых проверок |
| `getInfo()` | `machineId`, `version`, `os`, `connectedAt`, `capabilities` |

`capabilities` — честная карта возможностей **этой** машины, определяется один раз при старте службы:

```ts
{ launchGames, displayModes, brightness, telemetry,
  nvidiaProfiles,        // false на AMD/Intel и консолях
  workstationLock, restart,
  nativePanels: NativePanelTarget[] }  // только реально существующие панели
```

Если возможности нет — `false` / отсутствие в `nativePanels`. Не «true, но вернём ошибку при вызове»: лаунчер строит по этой карте disabled-состояния заранее.

### 3.2 Игры

| Метод | Требование |
|---|---|
| `getInstalledGames()` | Скан Steam/Epic/Riot/Battle.net/EA/Ubisoft + standalone. `needsUpdate: true` для обновляющихся — такой тайтл нельзя показывать готовым к игре |
| `launchGame(gameId, opts)` | Resolve **только** после появления окна игры. До этого — push `launch.progress` с монотонным `percent` и `step` из фиксированного набора: `queued`, `checkingFiles`, `syncingCloudSaves`, `startingLauncher`, `signingIn`, `startingGame`, `waitingForWindow` |
| | Два параллельных запуска запрещены: второй → `gameAlreadyRunning` с `detail = gameId` первого |
| | Поддержка отмены: лаунчер закрывает запрос → агент гасит процессы, поднятые этим запуском |
| `killGame(gameId)` | Сначала мягкое закрытие окна, через 10 с — `TerminateProcess`. Нет процесса → `gameNotRunning` |

Соответствие `gameId` каталогу клуба задаётся конфигом агента (`gameId` → launcher + appId/путь), а не эвристикой по имени файла.

### 3.3 Экран, яркость, GPU

| Метод | Требование |
|---|---|
| `getDisplayModes()` | Только режимы, которые монитор реально сообщил (EDID/QueryDisplayConfig). Лучший — первым |
| `setDisplayMode(mode, opts)` | **Применение всегда провизорное.** Возвращает `{ mode, previous, revertAt }`. Если `confirmDisplayMode()` не пришёл до `revertAt` (по умолчанию 15 с) — откат к `previous`. Чёрный экран не должен убивать оплаченную сессию |
| `confirmDisplayMode()` | Фиксирует последний провизорный режим. Нет ожидающего — no-op, не ошибка |
| `setBrightness(percent)` | `0`–`100`, возвращает фактически применённое значение. Панель без управления яркостью → `unsupported` |
| `getNvidiaProfiles()` | `[]` при `nvidiaProfiles: false`. `nameKey` — ключ словаря (`esports`, `balanced`, `quality`), не готовый текст |
| `applyNvidiaProfile(id)` | Возвращает обновлённый список с новым `active`. Не-NVIDIA → `unsupported`, неизвестный id → `invalidValue` |

### 3.4 Нативные панели

`openNativePanel(target)`, `target ∈` `nvidia-control-panel` \| `windows-display` \| `audio-output` \| `audio-input` \| `mouse` \| `keyboard`.

- Панель открывается **поверх** лаунчера и получает фокус.
- Цели, отсутствующей в `capabilities.nativePanels` → `unsupported`. Молча ничего не делать нельзя.
- Панель открывается от имени интерактивного пользователя сессии, не от `SYSTEM`.

### 3.5 Телеметрия

`getTelemetry()` → `{ fps, pingMs, cpuTempC, gpuTempC, cpuLoadPct, gpuLoadPct, diskUsedPct }`.

- Одно мгновенное чтение. Интервал держит вызывающая сторона — агент не рассылает телеметрию сам.
- `fps` — из оверлея запущенной игры; игры нет → `0`.
- Стоимость чтения — до 30 мс CPU. Телеметрия не имеет права воровать кадры у игры.

### 3.6 Управление станцией

| Метод | Требование |
|---|---|
| `lockWorkstation(reason)` | Полноэкранный экран блокировки поверх всего, `Alt+Tab` / `Win` / `Ctrl+Esc` / диспетчер задач недоступны. `reason ∈ sessionEnded \| break \| paymentRequired \| staff` определяет текст |
| `unlockWorkstation()` | Снимает **только** ту блокировку, которую поставил этот лаунчер, и только по команде с сервера (§7). Иначе → `permissionDenied` |
| `restartMachine(opts)` | `delaySec` — отсчёт для игрока. Во время оплаченной активной сессии → `blockedByPolicy` |

## 4. Локальное состояние агента

Агент хранит только то, что нужно для честных ответов и восстановления после падения:

- предыдущий режим экрана и время авто-откат�� (иначе падение агента оставит монитор в нерабочем режиме);
- текущий запуск (`launchId`, `pid`, `gameId`);
- факт и причину блокировки;
- собственную карту `capabilities`.

Никакой истории сессий, никаких сумм, никаких минут. При перезапуске службы: блокировка **сохраняется** (fail-secure), запущенные игры не убиваются, режим экрана откатывается, если откат не был подтверждён.

---

## 5. Поведение при потере сети

Агент и сервер связаны отдельно от лаунчера. Правила:

1. **Игра не прерывается ни при каких условиях.** Обрыв связи с сервером — не причина закрыть игру.
2. Блокировка, поставленная до обрыва, остаётся (fail-secure).
3. Блокировка **не** ставится по локальному таймеру: истечение времени без подтверждения сервера не блокирует ПК. Иначе рассинхронизация часов отберёт у игрока оплаченное время.
4. После восстановления агент запрашивает актуальное состояние и приводит станцию к нему одним шагом.

---

## 6. Безопасность и права

- Служба под `LocalSystem`; интерактивная часть (экран блокировки, панели) — в сессии пользователя через отдельный broker-процесс.
- У игрока нет прав администратора. Агент не выдаёт elevation ни одному запросу лаунчера.
- Белый список: агент запускает только пути из своего конфига. Произвольный путь из лаунчера принимать нельзя — иначе XSS в лаунчере превращается в исполнение кода на ПК.
- Логи: `%PROGRAMDATA%\IMBA\logs\agent-YYYY-MM-DD.log`, ротация 14 дней, без персональных данных.
- Обновление агента — только в момент, когда станция свободна.

## 7. Подписанные команды разблокировки

Разблокировка, продление и завершение сессии инициируются сервером. Формат команды:

```jsonc
{ "cmd": "unlock", "machineId": "pc-12", "sessionId": "s-901",
  "issuedAt": "2026-07-26T18:20:11Z", "nonce": "b3f1…", "sig": "<Ed25519>" }
```

- Публичный ключ клуба зашивается установщиком; проверка подписи обязательна.
- `issuedAt` старше 30 с — отказ. `nonce` повторно — отказ (защита от повтора).
- Команда без валидной подписи → `permissionDenied` + запись в лог. Лаунчер не может разблокировать ПК своими силами, даже если его код скомпрометирован.

## 8. Коды ошибок

Единый закрытый список (`AgentErrorCode`). Каждому коду соответствует ключ `errors.<code>` в словарях EN/RU/LT — агент не присылает текст.

| Код | Когда | Что делает лаунчер |
|---|---|---|
| `agentUnavailable` | агента нет / не отвечает | состояние F5.4: «Недоступно на этом ПК» + «Проверить снова» |
| `unsupported` | агент есть, железо не умеет | плитка disabled, «Недоступно на этом железе» |
| `agentTimeout` | принял и не ответил | предложить повтор |
| `gameNotInstalled` | нет на диске | «Не установлена», кнопка «Позвать админа» |
| `gameAlreadyRunning` | игра уже идёт | «Переключиться» / «Закрыть текущую» |
| `gameNotRunning` | закрыть/телеметрия без процесса | тихо синхронизировать состояние |
| `launcherFailed` | Steam/Epic/Riot не поднялся | повтор + «Позвать админа» |
| `permissionDenied` | Windows отказал / нет подписи | «Нужен администратор» |
| `invalidValue` | значение вне диапазона | вернуть контрол к прежнему значению |
| `blockedByPolicy` | запрещено правилами клуба | объяснить причину, действие не выполнять |
| `agentFailed` | всё прочее | общая ошибка + повтор |

## 9. Definition of Done для агента (Этап 5)

- [ ] Все методы `AgentBridge` реализованы; лаунчер работает без единой правки UI (замена только строки выбора реализации в `hooks/use-agent.ts`)
- [ ] `capabilities` честны на трёх стендах: NVIDIA-ПК, AMD-ПК, PS5-место
- [ ] Ложный успех невозможен: каждая невыполнимая операция возвращает код из §8
- [ ] Экран блокировки не обходится: `Alt+Tab`, `Win`, `Ctrl+Shift+Esc`, `Ctrl+Alt+Del`, второй монитор, перезагрузка по кнопке
- [ ] Провизорный режим экрана откатывается сам — проверено намеренно битым режимом
- [ ] Разблокировка без валидной подписи невозможна; повтор кадра отвергается
- [ ] Падение и перезапуск службы: блокировка сохранена, игра жива, режим экрана в норме
- [ ] Обрыв сети: игра не прервана, локальный таймер никого не блокирует
- [ ] Оверхед в простое: <1 % CPU, <80 МБ RAM; телеметрия не роняет FPS в игре
- [ ] Установщик: служба, токен, публичный ключ, автозапуск, тихое обновление
