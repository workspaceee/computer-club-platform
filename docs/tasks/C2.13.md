# C2.13 — Офлайн на входе (lock screen)

> Заполняет **чат-разведка** (сильная модель). Читает **чат-исполнение** и больше ничего:
> ни `PLAN.md`, ни `DESIGN.md`. Если исполнителю пришлось лезть в план — ТЗ написано плохо.
> Тип работы по `PLAN.md §0.5`: **C — архитектура и контракты** (трогает транспорт, репортёр

## 1. Что нужно сделать

`components/lock-screen.tsx` полностью слеп к обрыву связи: форма входа/PIN/QR/гость показывает
`errors.network` без связи с офлайн-баннером, а QR-логин ждёт `login.qr.confirmed`, который при
мёртвом канале не придёт никогда. Подпункт C2.13 закрывает **дверь клуба, пока нет связи**, но
объясняет почему и оставляет **одну** живую кнопку — «Позвать админа».

Принятые решения (следовать точно, это требования, а не варианты):

1. **Вход запрещён, но объяснён + зов админа.** При обрыве форма входа гасится одной фразой
   «Вход требует связи с клубом»; активна только кнопка «Позвать админа» (`callStaff` **не**
   блокируется). Все три двери C1.2 (логин / регистрация / гость), путь восстановления C1.3,
   подтверждение QR C1.5 и demo-вход C1.9 — под одним гейтом.
2. **Приостановленный визит по PIN тоже недоступен offline.** Сервер не подтвердит, кто ты и
   сколько времени осталось; резюм по банкнутым локальным секундам — это ровно баг C1.10.
3. **Запуск игры — да, house-аккаунт — нет** (договор C4.7/C4.8, закладывается **сейчас**).
   Установленная игра запускается offline (`catalog.launchGame` **не** в блок-листе). Игра,
   требующая house-аккаунта, честно скажет «выдача аккаунта требует связи» + «Позвать админа».
4. **Уже выданный house-аккаунт остаётся закреплённым** — обрыв его не отзывает (следствие: в
   блок-лист попадает только *выдача* аккаунта, никогда не *освобождение*).
5. **Репортёр отказов различает причину** (вход vs деньги): логин **не** должен получать тост
   «ничего не списано» — это про деньги, а не про дверь.

## 4. Как это уже сделано рядом (эталон)

**`useSalesGate()` — точный образец для `useEntryGate()`** (`hooks/use-sales-gate.ts`): заимствует
`offline` из `useRealtimeStatus()`, не заводит второй таймер, `useMemo`, возвращает булеву + причину.

```tsx
// hooks/use-entry-gate.ts — по образу use-sales-gate.ts
'use client'
import { useMemo } from 'react'
import { useRealtimeStatus } from '@/components/realtime/realtime-provider'

export type EntryBlockReason = 'offline'

export interface EntryGate {
  /** `true` когда дверь можно открывать. Единственное, что нужно кнопке «Войти». */
  canEnter: boolean
  /** Причина отказа, `null` пока вход открыт. */
  reason: EntryBlockReason | null
  /** Линк до сервера клуба лежит, дольше grace-периода баннера. */
  offline: boolean
}

export function useEntryGate(): EntryGate {
  const { offline } = useRealtimeStatus()
  return useMemo(
    () => ({ canEnter: !offline, reason: offline ? 'offline' : null, offline }),
    [offline],
  )
}
```

**Транспортный отбой — образец рядом в том же `mutate()`** (`lib/mock/api/client.ts`). Сейчас там:

```ts
if (linkOffline && OFFLINE_BLOCKED.has(endpoint)) {
  reportRefusal?.(endpoint)
  throw new ApiError('network')
}
```

Стать должно (порядок причин: деньги/вход обе кидают `network`, но с разным `kind` для тоста):

```ts
if (linkOffline) {
  if (OFFLINE_BLOCKED.has(endpoint)) {
    reportRefusal?.(endpoint, 'sales')
    throw new ApiError('network')
  }
  if (OFFLINE_ENTRY_BLOCKED.has(endpoint)) {
    reportRefusal?.(endpoint, 'entry')
    throw new ApiError('network')
  }
}
```

**Панель-заглушка «announced, not broken» — образец `GuestPanel`** внизу `lock-screen.tsx` и
`entry-offline` рядом с ним: тон `warning`, роль по шкале глубины (`well` / `pill`), иконка
`icons.offline`, `icons.staff` — те же, что баннер и гостевая панель уже используют. Никаких новых
цветов и `bg-black`. Вход — `framer-motion` `opacity+y`, `duration 0.25`.

**Как lock-screen уже прячет свитчер под состоянием** (строки ~868–886): `!blocked && !elsewhere &&
!pinCard && !recovery && signup?.step !== 'code' …`. Офлайн-гейт добавляется в тот же ряд условий и
в выбор ветки тела формы (`AnimatePresence mode="wait"`, строки ~891–1140): новая ветка
`!entry.canEnter` идёт **после** `blocked`/`elsewhere` (они выше по рангу — игрок уже прошёл
аутентификацию), но **выше** login/register/guest/recovery/pinCard.

**`callStaff`** (`lib/mock/api/support.ts:256`): `mutate('support.callStaff', …)`, не в блок-листах —
проходит офлайн. Тред идемпотентен (открытый уже есть → возвращает его). Экспортируется из
`@/lib/mock/api`.

## 6. Подводные камни

- **`callStaff` без залогиненного игрока.** На lock-screen `db.currentUserId` может быть `null`.
  `callStaff(payload, userId = db.currentUserId)` строит тред от `userId`. Проверить, что офлайн-зов
  админа работает при `null` (станция-аноним): если эндпоинт `requireAuth`-ит — добавить
  станционный/анонимный путь, а **не** прятать кнопку. Кнопка «Позвать админа» — единственная живая
  дверь офлайна, она обязана работать.
- **`OFFLINE_ENTRY_BLOCKED` объявлен, но не подключён.** Легко «увидеть набор в файле» и решить, что
  всё готово. Он не вызывается в `mutate()` — это половина задачи.
- **Тост «ничего не списано» на входе — главная ошибка, которую пункт чинит.** Пока репортёр один и
  всегда шлёт `realtime.salesRefused`. Без `kind` логин при офлайне соврёт про деньги.
- **Гейт заимствует `offline`, не заводит свой таймер.** Второй таймер разъедется с баннером: игрок
  увидит погашенную форму без баннера или наоборот. Один флаг, один момент — как в `useSalesGate`.
- **Мигание пакет-лосса.** Grace-период уже внутри `offline` (`OFFLINE_BANNER_DELAY_MS`) — 300 мс
  провал не должен гасить форму. Следствие заимствования флага, отдельно чинить не надо.
- **Ранг веток в `lock-screen`.** `blocked`/`elsewhere` (игрок уже аутентифицирован, карта про
  кресло/сессию) — **выше** офлайн-гейта; login/register/guest/recovery/pinCard — **ниже**. Не
  перекрыть панель «занято/играет на другом ПК» офлайн-панелью и наоборот.
- **PIN offline.** `pinCard` при офлайне не должен рисовать клавиатуру. `auth.unlockWithPin` уже в
  `OFFLINE_ENTRY_BLOCKED` (транспорт отобьёт), но UI обязан погасить ввод, а не давать нажать и ловить
  `network`. Причина — не резюмить визит по банкнутым локальным секундам (C1.10).
- **QR.** Диалог уже читает `useRealtimeStatus().offline` и показывает `auth.qrOffline`; `confirmQrChallenge`
  в блок-листе. Ничего доп. строить не надо — только проверить в браузере, что при обрыве он не
  «висит», а честно объясняет.
- **`useReconnectResync` на lock-screen.** Провайдер в root layout, значит ресинк жив и на логине.
  Он тянет снапшот только при `timerRunning` — на lock-screen таймера нет, ветка не сработает.
  Проверить, что реконнект на логине не дёргает `fetchCurrentSession` (иначе гарантированный
  `sessionExpired` каждый реконнект).
- **T1-неон.** У карты lock-screen уже есть один `neon-ring` (строка ~772). Офлайн-панель — T3
  (граница+материал+типографика), без второго T1, иначе `design:verify` R3 упадёт.
- **`bg-black` / инлайн-градиент.** Панель строится на ролях `well`/`pill` и тоне `warning/12`, как
  `GuestPanel` и баннер. Никакого `bg-black`, никакого инлайн-градиента затемнения (R1/R2).
