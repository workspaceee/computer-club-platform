# C2.14 — Идемпотентный `heartbeat`: клиент шлёт показание, а не дельту

> Заполняет **чат-разведка** (сильная модель). Читает **чат-исполнение** и больше ничего:
> ни `PLAN.md`, ни `OFFLINE-TIME.md`, ни `DESIGN.md`. Если исполнителю пришлось лезть в план —
> ТЗ написано плохо.
> Тип работы по `PLAN.md §0.5`: **C — архитектура и контракты** (трогает денежный контракт
> отчёта о времени, форму строки сессии и версию персиста) → рекомендуемая модель:
> **Opus 5 (сильная)**.

## 1. Что нужно сделать

`session.heartbeat` сегодня складывает: `session.secondsUsed += Math.min(burn, available)`
(`lib/mock/api/session.ts:245`). Это **дельта**, и она требует, чтобы каждый отчёт дошёл ровно
один раз. Любая сверка после обрыва — это цепочка ретраев, поэтому двойное списание здесь
наступает не «иногда», а по построению: потерялся *ответ* — клиент повторит то же самое, и
сервер спишет минуты второй раз.

Пункт переводит отчёт на **показание**: клиент говорит «от анкора `A` прошло `520` секунд», а
сервер берёт максимум. Из этого бесплатно следуют идемпотентность (повтор безопасен),
устойчивость к переупорядочиванию (отставшее `480` после `520` ничего не откатывает) и
отсутствие очереди отложенных операций (состояние синхронизации — одно число, а не журнал).

Принятые решения (следовать точно, это требования, а не варианты):

1. **Тело отчёта — `{ anchorId, elapsedSinceAnchor }`.** Не «сколько всего сыграно» и не
   «+10 с». Показание всегда привязано к анкору, иначе после продления сервер сложит
   несравнимое: клиент мерит от дедлайна, который уже заменён.
2. **Сервер применяет `max`, а не `+=`.** Считать нужно **обе** половины счёта одним числом:
   `counted = max(secondsUsed + debtSeconds, baseAtAnchor + elapsedSinceAnchor)`. Два отдельных
   `max` по `secondsUsed` и по `debtSeconds` — это способ списать переход через границу
   гранта дважды.
3. **Показание от чужого `anchorId` — игнор.** Не ошибка, не `conflict`: в ответ обычный свежий
   снапшот, из которого клиент узнает новый анкор и переанкорится сам.
4. **Анкор двигает каждая запись, двигающая время** — включая сам принятый `heartbeat` (см. §6,
   это неочевидная половина пункта: без ротации на приёме показание перестаёт расти, и время
   вообще не списывается).
5. **Overrun сохраняется как есть, но считается от показания:** prepaid → `state: 'ended'`,
   `closedBy: 'timeout'`; postpaid → `debtSeconds`. На паузе показание не растёт —
   `unreportedSeconds()` уже отдаёт `0`.
6. **Метки `// TRUST` не снимаются** — сервер здесь по-прежнему мок, и новая денежная
   арифметика получает свою метку.

## 2. Готовность (Definition of Done этого пункта)

- [ ] Два одинаковых отчёта подряд списывают время **один** раз (`secondsUsed`/`debtSeconds`
      после второго не изменились).
- [ ] Отчёт с прошлым `anchorId` не двигает **ничего** и получает в ответ свежий снапшот
      (не ошибку).
- [ ] Продление (`extendSession`) / выдача админом (`grantTime`) в середине визита не теряет и
      не удваивает минуты: анкор сменился, старое показание игнорируется, новое считается от
      нового `baseAtAnchor`.
- [ ] Показание, перескочившее грант, ведёт себя как раньше: prepaid → `ended` + `timeout`,
      postpaid → растущий `debtSeconds`; повтор того же показания долг **не** удваивает.
- [ ] На паузе показание не растёт, отчёт на паузе ничего не списывает.
- [ ] `SessionSnapshot.anchorId` печатают **оба** сборщика снапшота — `lib/mock/api/session.ts`
      и дубль в `lib/realtime/admin-sim.ts`.
- [ ] `SCHEMA_VERSION` персиста поднят: старый снапшот из localStorage не восстанавливает
      сессии без анкора.
- [ ] Клиент запоминает `anchorId` из снапшота и прикладывает его к отчёту; путь применения
      серверной правды остался **один** — `applySnapshot()`.
- [ ] `pnpm design:verify`, `pnpm icons:verify`, `next build`, `tsc --noEmit` — зелёные.

## 4. Как это уже сделано рядом (эталон)

**Ротация — рядом со строкой, а не в двух API-модулях.** Правило «время сдвинулось → эпоха
новая» должно жить в `lib/mock/db.ts`, потому что и мок-API, и `admin-sim` пишут одну и ту же
строку, а дубль правила разъедется:

```ts
// lib/mock/db.ts — рядом с getSession()/getLiveSession()
/**
 * Новая эпоха учёта на строке визита.
 *
 * Зовётся **каждой** записью, двигающей время: продление, выдача и коррекция админом,
 * пауза, возобновление, открытие/адопция визита и принятый `heartbeat`. Смысл — сделать
 * старое показание неприменимым: клиент мерил elapsed от дедлайна, которого больше нет,
 * и сложение его с новым `baseAtAnchor` было бы временем, никем не сыгранным.
 *
 * `baseAtAnchor` — **обе** половины счёта клуба, потому что показание сравнивается с ними
 * как с одним числом (prepaid жжёт `secondsUsed`, postpaid копит `debtSeconds`, и граница
 * между ними проходится ровно один раз).
 *
 * Идентификатор случайный, а не счётчик: после `F5` модульный счётчик начнётся заново, и
 * ротация могла бы вернуть строке анкор, который у неё уже был — то есть сделать
 * отставший отчёт из прошлой жизни вкладки применимым.
 */
export function reanchorSession(session: Session): void {
  session.anchorId = `${session.id}#${Math.random().toString(36).slice(2, 8)}`
  session.baseAtAnchor = session.secondsUsed + session.debtSeconds
}
```

**Сам `heartbeat`** (`lib/mock/api/session.ts:238`) становится таким; форма и порядок веток —
требование, а не набросок:

```ts
export function heartbeat(report: SessionReport): Promise<SessionSnapshot> {
  return mutate('session.heartbeat', () => {
    const session = required(getSession(db.currentSessionId), 'sessionExpired')
    if (session.state !== 'active') return snapshot(session)
    // Показание от прошлой эпохи: игнор, но с обычным ответом — из него клиент
    // и узнает про новый анкор, поэтому «отбить ошибкой» было бы тупиком.
    if (report.anchorId !== session.anchorId) return snapshot(session)

    const elapsed = Math.max(0, Math.floor(report.elapsedSinceAnchor))
    const reading = session.baseAtAnchor + elapsed
    // TRUST: сервер обязан пересчитать (Этап 4) — ниже деньги: `max` по сумме двух
    // половин счёта, а не по каждой отдельно.
    const counted = Math.max(session.secondsUsed + session.debtSeconds, reading)

    session.secondsUsed = Math.min(counted, session.secondsGranted)
    const overrun = counted - session.secondsGranted
    if (overrun > 0) {
      if (session.billingMode === 'postpaid') {
        // Присваивание, а не `+=`: `counted` уже монотонен, поэтому повтор
        // показания долг не удваивает.
        session.debtSeconds = overrun
      } else {
        session.state = 'ended'
        session.endedAt = db.now
        session.closedBy = 'timeout'
      }
    }

    // Отчёт принят — значит следующий пойдёт от нового рубежа (§6).
    reanchorSession(session)
    return snapshot(session)
  })
}
```

**Селектор отчёта — рядом с `unreportedSeconds`**, второго способа посчитать «сколько клуб не
слышал» не заводим:

```ts
// lib/store/slices/session.ts — сразу после unreportedSeconds()
/**
 * Отчёт, который клиент имеет право отправить, или `null` когда отправлять нечего.
 *
 * `null` — это «молчать», а не «послать ноль»: без анкора (визит открыт локально, снапшота
 * ещё не было) серверу нечего сопоставлять, а нулевое показание — запрос без содержания.
 */
export function sessionReport(
  s: Parameters<typeof unreportedSeconds>[0] & { anchorId: ID | null },
): SessionReport | null {
  if (!s.anchorId) return null
  const elapsed = unreportedSeconds(s)
  return elapsed > 0 ? { anchorId: s.anchorId, elapsedSinceAnchor: elapsed } : null
}
```

**`holdSeat`** (`lib/seat.ts:154`) меняет только аргумент, сохраняя свой докблок про «отчёт
перед паузой»: `if (report) await heartbeat(report).catch(() => {})`.

**Сид-строки** (`lib/mock/db.ts:763–861`) — `baseAtAnchor` равен `secondsUsed + debtSeconds`
той же строки (для `sess-demo` это `96 * 60`), `anchorId` — литерал вида `sess-demo#seed`.
Расхождение здесь читается как «клуб уже слышал больше, чем записал», и первый же отчёт
демо-визита спишет лишнее.

## 5. Данные и текст

**Типы (весь новый контракт):**

```ts
// lib/types/session.ts
export interface SessionReport {
  /** Эпоха, от которой мерено. Не совпал — сервер не двигает ничего. */
  anchorId: ID
  /** Секунды, прошедшие с анкора. Показание, а не дельта: повтор безопасен. */
  elapsedSinceAnchor: Seconds
}
```
и `anchorId: ID` в `SessionSnapshot`.

**Мок-API:** имя эндпоинта `session.heartbeat` не меняется, в блок-листы не добавляется.
Ошибок у него по-прежнему одна — `sessionExpired`.

**Dev-аффорданс** (`components/dev-kit/bus-console.tsx`, MOCK ONLY, английский, словари не
трогаем — это дев-поверхность): группа `report` / «Ledger report» с тремя кнопками, ровно под
три проверки §7, плюс панель `LEDGER` справа, где видно `used / debt / anchor` из ответа:

- **`Report +30 s`** — берёт `anchorId` из последнего ответа (или из снапшота
  `fetchCurrentSession`) и шлёт `{ anchorId, elapsedSinceAnchor: 30 }`; **запоминает
  отправленное тело** в модульной переменной.
- **`Re-send the same report`** — шлёт **тот же самый** объект ещё раз. Списание не должно
  измениться: это и есть идемпотентность.
- **`Report with a stale anchor`** — шлёт запомненное тело с `anchorId: 'stale'`. `used` и
  `debt` не двигаются, ответ приходит нормальным снапшотом.

Кнопки асинхронные, а существующий `fire()` ловит только синхронные ошибки — обернуть
(`void run().catch(...)` внутри самого `run`), иначе отказ уйдёт в unhandled rejection.
Тон/роли — как у соседних групп (`Panel`, `Badge`, `Button size="sm"`), новых цветов и
`bg-black` не заводим.

**Числа:** секунды целые, всё флорится в нуль. Денег этот пункт не считает: `tabTotalCents`
приходит из уже существующего `getOpenTab`, `POSTPAID_CENTS_PER_MINUTE` не трогаем.

**i18n:** новых пользовательских строк нет — игрок про отчёт ничего не видит и не должен.

## 6. Подводные камни

- **Ротация на принятом отчёте — обязательна, и это неочевидно.** `unreportedSeconds()` мерит
  время **от последнего применённого снапшота** (`atAnchor - derive()`), а не от начала эпохи.
  Значит, если сервер не сдвинет `baseAtAnchor` при приёме, картина будет такой: отчёт
  `elapsed=10` → `used=10`; клиент применил ответ, его elapsed обнулился; следующий отчёт опять
  `elapsed=10` → `max(10, 0+10) = 10`. **Время перестаёт списываться совсем.** Поэтому принятый
  отчёт заканчивается `reanchorSession()`.
- **Цена ротации — потерянное окно при потерянном ответе,** и это осознанный выбор. Ответ не
  дошёл → клиент повторит с уже неактуальным анкором → игнор, но в ответ придёт свежий снапшот,
  клиент переанкорится, и потеряется максимум один интервал отчёта. Недоотчёт — безопасное
  направление (клуб не выставил счёт); переотчёт — опасное (игрок заплатил за то, чего не
  играл). Альтернатива (сервер анкор не двигает, а клиент сам накапливает показание) требует
  второго аккумулятора на клиенте, который выживает `applySnapshot`, — то есть ровно того
  второго мнения о времени, которого в этом блоке нет ни у кого. **Не делать.**
- **Офлайн работает именно потому, что анкор не двигается без ответа.** Пока связи нет,
  снапшотов не приходит, `unreportedSeconds()` растёт `40 → 510 → 520`, и один запрос на
  реконнекте догоняет леджер (`C2.16` это и использует). Никакой очереди.
- **`max` берётся по сумме, а не по половинам.** `secondsUsed` у postpaid-строки может стоять
  на `secondsGranted` (у сидовой `sess-maya` грант вообще `2 ч`), а дальше растёт только долг.
  Два независимых `max` дадут двойной счёт на переходе через границу гранта.
- **`debtSeconds` присваивается, а не прибавляется.** `+=` на идемпотентном показании — это тот
  же баг, который пункт чинит, просто переехавший в долг.
- **Персист.** `SCHEMA_VERSION` обязан вырасти: v5-снапшот восстановит `sessions` **без**
  `anchorId`, и `undefined !== session.anchorId` — тогда каждый отчёт будет молча игнорироваться
  навсегда, в каждом браузере, который когда-либо открывал демо. Диагностировать это
  «изнутри продукта» невозможно: экран идёт ровно, а сервер не слышит.
- **Два сборщика снапшота.** `admin-sim` держит **копию** `snapshot()` намеренно (в этапе 4
  снапшот собирает сервер). Забыть про `anchorId` там — значит выдать клиенту снапшот без
  анкора после `+15 min`, и следующий отчёт улетит в игнор.
- **`warnLowTime` тоже двигает время** (`session.secondsUsed = max(...)`, `admin-sim:198`) — это
  запись, двигающая счёт, и ей нужна ротация, иначе `baseAtAnchor` останется позади факта.
- **Адопция визита в `openSession`** (`:411–421`) — тоже начало новой эпохи: игрок вернулся в
  строку, клиент придёт с анкором из ответа, а прошлые показания (например, из другой вкладки)
  применяться не должны.
- **`pausedSeconds` не трогаем.** Поле на строке существует и этим пунктом не заполняется —
  соблазн «раз уж мы тут» ведёт к третьему счётчику времени.
- **Порядок в `heartbeat`: сначала `state !== 'active'`, потом сверка анкора.** На паузе
  показание игнорируется независимо от анкора, и ответ обязан быть снапшотом — иначе
  «отчёт на паузе» станет ошибкой на пути, который штатно случается каждый lock.
- **`SessionReport | null` в `holdSeat`.** Три вызова передают результат селектора напрямую;
  ветка `null` (нечего отчитывать) существовала и раньше как `usedSeconds > 0`.

   анкор от до-продления) → игнор; затем `Report +30 s` → списалось ровно 30, остаток на
   клоке лаунчера не дёрнулся.
4. **Prepaid догорает.** `Warn: 2 min left`, затем `Report +30 s` несколько раз до перехода
   через ноль → строка `ended` / `timeout`, повтор того же показания ничего не добавляет.
5. **Postpaid.** Гостевой визит (`/?seat=guest` или гостевой вход): `Report +30 s` растит
   `debt`, `Re-send` — нет.
6. **Пауза.** `Pause seat` → `Report +30 s` → ни `used`, ни `debt` не выросли.
7. **Lock PC.** «Заблокировать ПК» из меню профиля: остаток на паузной карте совпадает с
   тем, что был на клоке (регресс C1.10 — отчёт перед паузой должен доходить).
8. **Персист.** `F5` после нескольких отчётов: визит на месте, следующий `Report +30 s`
   принимается (а не игнорируется) — значит анкор пережил перезагрузку.
