## 1. Что нужно сделать

Дословно из плана:

> **C4.12** Жалобы на клубные аккаунты: игрок сообщает о нерабочем/забаненном логине → строка уходит в
> **карантин** (исключена из выдачи, освобождена от сессии) → админ в `/dev/bus` решает «починил →
> вернуть в пул» или «отклонить» → событие `account.updated` возвращает счётчики и поднимает тост игроку.

Зачем: после `C4.7` клуб выдаёт логин автоматически, и у игрока нет ни одного способа сказать, что
выданный логин забанен или не пускает. Сейчас его единственный выход — перезапускать игру, каждый раз
получая ту же мёртвую строку: `grantHouseAccount` идемпотентен и возвращает уже закреплённый аккаунт.

## 4. Как это сделать (принятые решения)

**Карантин — статус, а не удаление.** Строка остаётся в пуле и видна («на проверке»), потому что
исчезнувшая строка читается как «клуб потерял аккаунт», а админу нужно на что-то нажать. Выдача
фильтрует по `status === 'available'`, значит карантин выпадает из неё **без правок гранта** — но это
надо проверить глазами: любая проверка вида `status !== 'in-use'` начнёт выдавать карантин.

**Жалоба очищает грант.** Иначе строка остаётся «за тобой», `fetchAssignedHouseAccount` продолжает
печатать её в полосе, а повторный запуск идемпотентно вернёт тот же мёртвый логин:

```ts
export function reportHouseAccount(
  accountId: ID,
  reason: HouseAccountReportReason,
  comment?: string,
): Promise<HouseAccountReport> {
  return mutate('catalog.reportHouseAccount', () => {
    const account = db.houseAccounts.find((a) => a.id === accountId)
    // Пожаловаться можно только на свою строку: чужая жалоба выводит из пула
    // логин, которым в этот момент кто-то играет.
    if (!account || account.sessionId !== db.currentSessionId) throw new ApiError('notFound')

    const report: HouseAccountReport = { /* … status: 'open', createdAt: nowIso() … */ }
    db.houseAccountReports.unshift(report)

    // Карантин + освобождение одним движением: строка выведена из выдачи и
    // больше не «за тобой».
    account.status = 'quarantined'
    account.sessionId = undefined
    return report
  })
}
```

`accountLabel` кладём **в саму жалобу**: админке и тосту иначе нужен второй проход по пулу, а после
вердикта строка уже могла быть переименована.

**Почему жалоба разрешена офлайн.** По той же логике, что и `releaseHouseAccount`: жалоба **отдаёт**
клубный ресурс и безопасна поздно, а блокировка оставила бы битый логин в обороте и молча вернула бы
его следующему гостю. В `OFFLINE_BLOCKED` не добавляем — это осознанное решение, не забывчивость.

**Диалог жалобы** — маленький модал по образцу `game-launch-modal.tsx` (`Overlay` + `useDismissableLayer`,
`Esc`, клик вне, focus trap). Радио-список причин — `role="radiogroup"`, комментарий — `Field`
(`components/ui/field.tsx`), кнопки — `Button` из дизайн-системы. **T1-неона нет** — диалог не главное
действие экрана (§4.2, `design:verify` R3).

**Сценарий отправки — четыре шага в одном обработчике**, порядок важен:

```ts
await reportHouseAccount(assigned.accountId, reason, comment || undefined)
// Под битым логином игра всё равно не живёт, и оставленный процесс держит место
// занятым: следующий запуск ответит `gameAlreadyRunning`.
void mockAgent.killGame(runningGameId).catch(() => {})
setRunningGame(null)
invalidate('catalog')
toast('info', t('games.accountReportSent'))
```

Тост нейтральный, не `error`: игрок сделал нормальную вещь, а не сломал лаунчер.

**Вердикт админа — оба возвращают строку в пул.** `fixed` → жалоба `resolved`, аккаунт `available`;
`dismissed` → жалоба `dismissed`, аккаунт **тоже** `available` (админ проверил — логин рабочий). Если
админ считает аккаунт мёртвым, он просто не жмёт ничего: строка остаётся в карантине. Отдельного
статуса «мёртв» не заводим — это админка Этапа 3.

**Событие.** Порядок как у всех действий симулятора: запись в `db` → `commit()` → `mockBus.publish`.
Пейлоад `{ accountId, label, status, reportId, resolution: 'fixed' | 'dismissed' | null }`, тон в карте
— `'info'` (одна запись на имя события; «починен» не громче «отклонён»), `EVENT_INVALIDATES` →
`['catalog']`: строка полосы, счётчики плиток и список пула обновятся одним пушем. Тост игроку рождается
приёмником события — **проверить `realtime-provider.tsx`**: если тосты собираются per-event, добавить
ветку для `account.updated`, читающую `notifications.accountFixed` / `accountDismissed`.

**Секция в `bus-console`.** Статичный `GROUPS` не подходит: жалобы появляются в рантайме. Отдельный
компонент в этом же файле, читает `fetchHouseAccountReports()`, перечитывает по `useRealtimeAny` и
после каждого нажатия. Строка = ярлык + причина + время (`formatCountdown`/локальное время, не
`new Date().toString()` в JSX), кнопки `Fix & return` (`tone: 'success'`) и `Dismiss` (нейтральный).

## 6. Подводные камни

- **Утёкший карантин.** Жалоба обязана очистить `sessionId`. Строка `quarantined`, всё ещё привязанная
  к сессии, не выдаётся никому **и** печатается в полосе «В игре» как «твой аккаунт» — худшее из двух.
- **Освобождение остаётся в двух местах.** Жалоба сама переводит строку в карантин, поэтому
  `releaseHouseAccount` из `in-game-strip` в этой ветке звать **не надо** — иначе карантин
  немедленно превратится в `available`, и мёртвый логин уедет следующему гостю.
- **Третий тон точки.** Статусов стало три — проверить все места, где рисуется двухзначная точка
  (`accountInUse` / `accountAvailable`): бинарная тернарка молча покажет карантин как «свободен».
- **Счётчики `C4.11`.** `free` считается как `status === 'available'`, а не `!== 'in-use'` — иначе
  карантин попадёт в «свободно».
- **Порядок в симуляторе.** `db` → `commit()` → `publish`. Публикация до `commit()` даст клиенту
  инвалидацию раньше, чем состояние попадёт в снапшот.
- **`persist.ts` — три места.** Массив, добавленный в `db` и забытый в снапшоте, обнулит жалобы на
  первой перезагрузке страницы, и «админ починил» перестанет воспроизводиться.
- **Дубль уведомления.** Не звать `staffMessage` вдогонку событию: игрок получит два тоста об одном.

## 7. Проверка

```
pnpm design:verify
pnpm icons:verify
pnpm build
```

Полный прогон в браузере (1920×1080 и 1366×768), демо-режим:

1. Клубный запуск → «Аккаунт IMBA_0X закреплён за тобой», рядом pill «Пожаловаться».
2. Жалоба «Забанен в игре» + комментарий → диалог закрылся, игра снята, тост нейтральный.
3. Модал запуска: строка `IMBA_0X` приглушена, подпись «на проверке», счётчик «свободно» уменьшился
   на единицу, «занято» не выросло.
4. Повторный запуск той же игры → выдан **другой** аккаунт (или очередь, если пул исчерпан).
5. `/dev/bus` → секция «House accounts»: одна открытая жалоба с ярлыком, причиной и временем.
6. `Fix & return` → тост игроку `notifications.accountFixed`, строка вернулась в «свободно» без
   перезагрузки страницы.
7. `Dismiss` на второй жалобе → тост `accountDismissed`, строка тоже вернулась.
8. Перезагрузка страницы с открытой жалобой → жалоба на месте (persist).
9. Пустая панель: «No reports — the pool is clean».
10. Клавиатура: диалог жалобы открывается и закрывается с клавиатуры, `Esc` работает, фокус
    возвращается на pill.
