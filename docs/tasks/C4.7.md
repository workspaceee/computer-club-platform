## 1. Что нужно сделать

Дословно из плана:

> **C4.7** House-аккаунты: если игра требует общий аккаунт — автоматическая выдача свободного, показ
> «Аккаунт IMBA_04 закреплён за тобой на время сессии», обработка «все аккаунты заняты» с кнопкой
> «Занять очередь»

Что за этим стоит в коде. После `C4.6` строка чеклиста «Выдача аккаунта» — это **подтверждение
`catalog.launchGame`**, то есть подпись без действия: никакой выдачи нет, ничего не закрепляется, а
список аккаунтов в диалоге — ручной выбор, который дальше компонента не уходит. Пункт превращает
подпись в настоящую серверную выдачу: игра с `needsHouseAccount` получает свободный аккаунт из пула
клуба автоматически, игрок видит какой именно и на какой срок, а когда пула не хватило — получает
очередь вместо «спроси администратора».

## 4. Как это уже сделано рядом (эталон) и принятые решения

**Порядок вызовов в хуке.** Выдача — предусловие запуска, а не одна из параллельных задач: игра не
должна подниматься без аккаунта, а аккаунт не должен уходить в `in-use` под запуск, который не
состоялся. Поэтому выдача идёт **до** пары «эндпоинт + агент», внутри того же `try` (шапку
`C4.6` не переписывать, только вставить шаг):

```ts
const controller = new AbortController()
let grant: HouseAccountGrant | null = null
try {
  if (game.needsHouseAccount) {
    // Строка «Выдача аккаунта» активна ровно на этом await.
    grant = await grantHouseAccount(game.id)
    if (alive.current) setState((prev) => ({ ...prev, grant }))
  }
  const [, handle] = await Promise.all([
    launchGame(game.id).catch((err) => { controller.abort(); throw err }),
    agent.launchGame(game.id, {
      onProgress,
      signal: controller.signal,
      houseAccountId: grant?.accountId,
    }),
  ])
  …
} catch (err) {
  // Аккаунт, выданный под запуск, который не поднялся, обязан вернуться в пул.
  if (grant) void releaseHouseAccount(grant.accountId).catch(() => {})
  …
}
```

Ветка отмены (`cancelledRef`) идёт через тот же `catch`, так что освобождение при отмене получается
бесплатно — **проверить, что оно действительно происходит**, это отдельный сценарий приёмки (§7.4).

**Строка `account` в чеклисте** становится условной. `LAUNCH_STEPS` остаётся полным списком, а хук
отдаёт наружу видимый набор:

```ts
/** Строки для этого запуска: игра без общего аккаунта не показывает «Выдачу». */
steps: readonly LaunchStepId[]  // = needsHouseAccount ? LAUNCH_STEPS : без 'account'
```

Диалог рисует `steps`, а не `LAUNCH_STEPS`. Пустая активная строка на игре, которой аккаунт не нужен,
— ровно та фикция, от которой ушли в `C4.6`.

**Кто владеет фактом «аккаунт закреплён» — сервер.** Закрепление живёт на сессии, а не на кадре
запуска: игрок увидит его в полосе «В игре» через минуту после того, как диалог закрылся, и после
перезагрузки оболочки тоже. Поэтому:

- источник — чтение `fetchAssignedHouseAccount()` с ключом `useApi('catalog/assigned-account', …)`;
- после выдачи и после освобождения — `useInvalidate('catalog')`, как это делают остальные записи;
- в сторе не появляется ничего: `launchingGameId` / `runningGameId` остаются единственными
  глобальными фактами запуска (правило `C4.6`).

Хук всё равно отдаёт `grant` наружу — но только чтобы диалог показал строку **в тот же кадр**, без
ожидания рефетча. Постоянный показ (полоса «В игре») читает сервер.

**Ручной список аккаунтов в диалоге.** Он остаётся, но перестаёт быть выбором «чем запускать»:
выдача автоматическая, и `catalog.grantHouseAccount` принимает только `gameId` — какой именно
аккаунт свободен, решает клуб. Список превращается в **состояние пула**: строки с `accountInUse` /
`accountAvailable` как сейчас, но без `onClick`, без предвыбора и без чекбокса
`games.rememberAccount` (запоминать нечего — выбора нет; ключ из словарей **удалить** во всех трёх,
как удаляли `launchStepSession` в C4.6). Кнопка «Запустить» перестаёт зависеть от `account`:
`disabled={!game || blocked}`.

**Панель «все аккаунты заняты»** — новое состояние того же диалога, не новый оверлей. Эталон
разметки и тона — `EmptyState` в `bare size="sm"` виде, уже стоящий в этом же файле на
`games.noAccounts`, и панель `components/launcher/offline-tab-cap.tsx` для случая «объяснили и дали
одно действие». Кнопка «Занять очередь» — стилем существующей primary из футера, без второго T1:

```tsx
<EmptyState
  bare
  size="sm"
  icon={icons.accountMissing}
  title={t('games.noAccounts')}
  description={t('games.houseAccountQueueBody')}
/>
```

Под ней — либо кнопка `games.houseAccountQueueJoin`, либо, если билет уже есть, строка
`games.houseAccountQueuePosition` (`icons.timer`) + текстовая кнопка `games.houseAccountQueueLeave`.

**«Все заняты» при быстром запуске.** `continue-row` не имеет места под панель, а показывать очередь
двумя разными кусками вёрстки нельзя. Решение: в ветке `noFreeAccount` хук поднимает тост
`games.houseAccountBusy` **и** делает `setLaunchGame(game.id)` — открывает диалог этой игры, где
панель очереди уже есть. Один кусок UI, оба входа.

**Освобождение.** Два места и ни одного больше: `catch` в хуке (запуск не состоялся, см. выше) и
кнопка «Игра закрыта» в `in-game-strip.tsx` рядом с существующим `killGame` + `setRunningGame(null)`.
Конец сессии пул не чистит — это серверная работа Этапа 4, писать её здесь не нужно.

**Ошибка «нет свободного аккаунта» — код, а не текст.** `ApiErrorCode` пополняется одним значением
`noFreeAccount` (`STATUS: 409`, рядом с `outOfStock` — это тот же смысл «клубного ресурса не
хватило»), словари получают `errors.noFreeAccount`. Хук отличает его через `toApiError(err).code`,
как это уже делает `hooks/use-extend-time.ts`.

## 5. Данные и текст

**Новые типы** (`lib/types/catalog.ts`, рядом с `HouseAccount`):

```ts
/** Ответ на выдачу: что закреплено, за кем и до какого момента. */
export interface HouseAccountGrant {
  accountId: ID
  /** Лейбл клуба — единственное, что показывается игроку («IMBA_04»). */
  label: string
  sessionId: ID
  gameId: ID
  grantedAt: ISODateTime
}

/** Билет в очереди на общий аккаунт. Позицию считает сервер. */
export interface HouseAccountQueueTicket {
  id: ID
  gameId: ID
  sessionId: ID
  /** 1 = следующий. Пересчитывается сервером при каждом чтении. */
  position: number
  joinedAt: ISODateTime
}
```

В `HouseAccount` добавить `sessionId?: ID` — иначе `in-use` не отличает «занят другим гостем» от
«закреплён за мной», а это ровно та разница, которую печатает строка закрепления.

**Мок-API** (`lib/mock/api/catalog.ts`, все записи через `mutate`, чтения через `query`):

| Функция | Эндпоинт | Поведение |
|---|---|---|
| `grantHouseAccount(gameId)` | `POST /api/club/accounts/grant` | если у сессии уже есть аккаунт на эту игру — вернуть его (идемпотентно); иначе первая строка `status === 'available'` **без** `linkedUser` → `in-use` + `sessionId`; если таких нет — `throw new ApiError('noFreeAccount')` |
| `releaseHouseAccount(accountId)` | `POST /api/club/accounts/release` | только если `sessionId` совпадает с текущей: `available`, `sessionId` снять. Чужую строку не трогает |
| `joinHouseAccountQueue(gameId)` | `POST /api/club/accounts/queue` | билет для текущей сессии, повторный вызов возвращает существующий; `position` = индекс в `db.houseAccountQueue` + 1 |
| `leaveHouseAccountQueue(gameId)` | `DELETE /api/club/accounts/queue` | убрать билет, остальные позиции пересчитываются чтением |
| `fetchAssignedHouseAccount()` | `GET /api/club/accounts/mine` | `HouseAccountGrant \| null` для текущей сессии |

`linkedUser`-строка (`personal`) из выдачи **исключена**: это личный аккаунт игрока, а не пул клуба —
клуб не имеет права выдать его другому гостю.

Ключи `useApi`: `'catalog/house-accounts'` (уже есть), `'catalog/assigned-account'`,
`'catalog/house-queue'`. Все три под одним префиксом `catalog`, так что `useInvalidate('catalog')`
после выдачи / освобождения / очереди накрывает их одним вызовом. `EVENT_INVALIDATES` не трогаем —
нового события нет.

## 6. Подводные камни

- **Третий вид отказа.** `catalog.grantHouseAccount` уже в `OFFLINE_BLOCKED` (`client.ts:309`), а
  репортёр знает только `'sales'` и `'entry'` — значит **сейчас** офлайн-выдача покажет
  `realtime.salesRefused` («деньги не списаны») над запуском игры, где денег не было. Ровно та
  ошибка, из-за которой в `C2.13` появился второй `kind`. Расширить `RefusalKind` до
  `'sales' | 'entry' | 'account'`, поставить `'account'` обеим записям про аккаунты и добавить третью
  ветку в `realtime-provider.tsx:148` → `games.houseAccountOfflineBody`. Больше в этом файле ничего.
- **Очередь тоже блокируется офлайн, освобождение — никогда.** Позицию в очереди назначает клуб;
  локальное «ты третий» — выдуманное число, поэтому `catalog.joinHouseAccountQueue` идёт в
  `OFFLINE_BLOCKED`. А `catalog.releaseHouseAccount` в список **не** попадает ни при каких условиях:
  освобождение отдаёт клубный ресурс и безопасно быть исполненным поздно — правило записано в
  комментарии к списку, не переписывать его.
- **Игра без общего аккаунта офлайн запускается.** `catalog.launchGame` вне обоих списков, и это не
  меняется. Гейт на офлайн вешаем **только** на ветку `needsHouseAccount`: проверить
  `isTransportOffline()` до вызова и отказать копией `games.houseAccountOffline*`, не начиная запуск,
  — иначе игрок увидит чеклист, который заведомо упадёт.
- **Аккаунт не должен утекать.** Любой выход из `try` после успешной выдачи — ошибка эндпоинта,
  ошибка агента, отмена игроком, размонтирование — обязан вызвать `releaseHouseAccount`. Утёкшая
  строка `in-use` не лечится ничем, кроме перезапуска мока, и в проде это гость, который не может
  играть, потому что аккаунт «занят» мёртвой сессией.
- **Идемпотентность выдачи.** Повторный запуск той же игры в той же сессии не должен съедать второй
  аккаунт: `grantHouseAccount` сначала ищет уже закреплённый за `db.currentSessionId` и возвращает
  его. Иначе три перезапуска CS2 выносят весь пул.
- **Освобождения по событию в этом пункте нет.** Очередь — это заявка, а не подписка: строка
  «освободился, забирай» требует серверного пуша (`house-account.freed`), которого нет в
  `lib/realtime/events.ts`, и админ-симулятора, который его отправит. Не изобретать здесь: билет
  просто существует, копия обещает «лаунчер сообщит», а сам пуш — **долг** на `A2`/`A3` (карта зала
  и сессии) или на `B1.4`. Записать его в отчёт как долг.
- **`persist.ts`.** Новый массив в `db` без правки трёх мест снапшота — это очередь, которая
  исчезает при перезагрузке страницы, но `houseAccounts` при этом сохраняются: пул останется занят,
  а билеты пропадут.
- **Высота.** 693 px и самый высокий диалог продукта. Панель очереди рисуется **вместо** списка
  аккаунтов, а не под ним; строка закрепления — одна строка `text-sm` под чеклистом, не карточка.
- **Дизайн-запреты.** Только токены (`text-success`, `text-primary`, `text-text-low`, `bg-danger`),
  никаких hex/rgb/oklch, `bg-black`, `text-white`. Иконки — только `lib/icons.ts`
  (`icons.accountMissing`, `icons.timer`, `icons.check`), эмодзи запрещены. Второй T1-неон в диалоге
  не добавлять: свечение уже на «Запустить», кнопка очереди живёт без него.
- **Долг от `C4.6`**, адресованный сюда, — только «источник строки “Выдача аккаунта” и офлайн-ветка
  на готовых ключах `games.houseAccountOffline*`». Больше ничего не унаследовано.
