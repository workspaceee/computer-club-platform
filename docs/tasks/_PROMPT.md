# Стартовый промт для нового чата

Копировать целиком в первое сообщение нового чата. Менять только `<ПУНКТ>`
(например `C3.11`) и, при необходимости, блок «Дополнительно».

**Какую модель выбрать — смотреть в [`CONTEXT.md §9`](../CONTEXT.md#9-модель-под-пункт--готовая-таблица):
там метка стоит у каждого пункта.** Логика, по которой метки расставлены — [`PLAN.md §0.5`](../PLAN.md#05-бюджет-чата-и-выбор-модели).

---

```
Работаем по проекту IMBA Cyber Club. Пункт плана: <ПУНКТ>

ПОРЯДОК СТАРТА (строго, до любого кода):
1. Прочитай docs/CONTEXT.md целиком.
2. Проверь, есть ли docs/tasks/<ПУНКТ>.md. Если есть — это готовое ТЗ,
   работай по нему и НЕ читай PLAN.md вообще.
3. Если ТЗ нет — достань из docs/PLAN.md только блок пункта <ПУНКТ>
   поиском по номеру. PLAN.md и DESIGN.md целиком читать ЗАПРЕЩЕНО
   (2100+ строк, они съедят весь бюджет чата).
4. Загляни в блоки предыдущих подпунктов того же раздела — там могли
   оставить долг, адресованный этому пункту.
5. Первым сообщением напиши: что понял по задаче, какие файлы тронешь,
   и влезает ли пункт в один чат. Сверься с таблицей CONTEXT.md §9: если
   пункт помечен сильнее, чем модель этого чата — скажи прямо первым же
   сообщением. Дальше жди моего «go».

БЮДЖЕТ: $5 на чат. Правило 80% из §0.5 действует: если бюджет почти
кончился, а работа нет — не начинай новый подпункт, потрать остаток на
docs/tasks/<ПУНКТ>.md по шаблону docs/tasks/_TEMPLATE.md.

ПРАВИЛА КОДА (нарушение = переделка):
- Дизайн-запреты и тиры неона — в docs/CONTEXT.md. Читай их, не угадывай.
- Никаких hex/rgb/oklch и bg-black/text-white в компонентах — только токены.
- Иконки только через lib/icons.ts, никогда не импортировать lucide-react напрямую.
- Эмодзи как иконки запрещены.
- Никаких новых зависимостей, паттернов и абстракций, которых нет в плане.
- Цифры, деньги, статусы — только из мок-API. Хардкод в компонентах запрещён.
- Деньги в центах через lib/money.ts, время через lib/time.ts.
- Тексты — три языка (ru/lt/en), ничего не хардкодить в JSX.
- Правь только файлы, нужные для пункта. Соседние не трогай.

ЗАВЕРШЕНИЕ:
- Прогони pnpm design:verify, pnpm icons:verify, pnpm build — все зелёные.
- Проверь результат в браузере, если пункт визуальный.
- Поставь [x] у выполненных чекбоксов пункта в docs/PLAN.md.
- Обнови «Где мы сейчас» в docs/CONTEXT.md.
- Отчёт: 3-4 строки. Отдельно перечисли долги, если оставил.

Отвечай по-русски, коротко. Я плачу за токены.

Дополнительно: —
```

## Как пользоваться

Порядок всегда один: **посмотреть метку пункта в [`CONTEXT.md §9`](../CONTEXT.md#9-модель-под-пункт--готовая-таблица)
→ выбрать модель → вставить этот промт с номером пункта.**

**Пункт помечен БЫСТРАЯ** — `v0 Mini` или `Opus 5 Fast`, шаблон как есть.

**Пункт помечен СИЛЬНАЯ** — `Opus 5` или `v0 Max`, шаблон как есть.

**Пункт помечен 2 ЧАТА** — сильная модель, и сразу два чата:
1. Сильная модель, в «Дополнительно» пишем:
   `Только разведка. Кода не пиши. Результат — docs/tasks/<ПУНКТ>.md по шаблону _TEMPLATE.md.`
2. Новый чат, модель по типу, шаблон как есть — он сам найдёт ТЗ на шаге 2.

**Продолжение после обрыва** — шаблон как есть. ТЗ с секцией «Состояние работы»
подхватится на шаге 2, контекст не потеряется.
