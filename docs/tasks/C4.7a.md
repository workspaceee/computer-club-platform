# C4.7a — Выбор в модале запуска: клубный аккаунт или свой

> Заполняет **чат-разведка** (сильная модель). Читает **чат-исполнение** и больше ничего:
> ни `PLAN.md`, ни `DESIGN.md`.
> Тип работы по [`PLAN.md §0.5`](../PLAN.md#05-бюджет-чата-и-выбор-модели): **C** (архитектура и контракты —
> правится договор `AgentBridge` и договор «кто выдаёт логин»)
> → рекомендуемая модель: **сильная (`Opus 5`)**, ТЗ + исполнение в двух чатах.

## 1. Что нужно сделать

В модале запуска игры, которая требует общий логин, игрок выбирает **режим входа**, а не строку пула:

- **«Клубный аккаунт»** — рядом счётчик «N свободно · M занято». При запуске сервер сам отдаёт один из
  свободных (`catalog.grantHouseAccount`, поведение C4.7 не меняется).
- **«Свой аккаунт»** — клуб не выдаёт ничего, агент открывает **чистый** лаунчер (например Steam) без
  клубной сессии, игрок логинится сам.

Выбор режима — единственное решение игрока. **Какой именно** клубный аккаунт достанется, по-прежнему
решает сервер: отдельные строки пула остаются некликабельными.

## 2. Готовность (Definition of Done этого пункта)

- [ ] В модале для игры с `needsHouseAccount: true` — две карточки-радио: клубный аккаунт и свой.
      Клавиатура: стрелки внутри группы, `Tab` — вход/выход из группы, состояние читается скринридером.
- [ ] На карточке клубного режима — счётчик свободных и занятых, посчитанный только по **выдаваемым**
      строкам пула (строки с `linkedUser` в счёт не идут).
- [ ] `Personal Steam Account` больше не висит в списке клубного пула. Привязанный логин, если он есть,
      печатается подписью на карточке «свой аккаунт».
- [ ] Запуск в режиме «клубный» = сегодняшний путь C4.7: grant → чеклист со строкой «Выдача аккаунта» →
      строка «Аккаунт IMBA_0X закреплён за тобой», релиз на любом выходе.
- [ ] Запуск в режиме «свой»: `grantHouseAccount` **не вызывается**, строки «Выдача аккаунта» в чеклисте
      нет, `releaseHouseAccount` вызывать нечего, агент получает режим и открывает лаунчер без входа.
- [ ] Пул пуст (`0 свободно`): режим «клубный» ведёт в панель очереди как сейчас, но режим «свой»
      остаётся доступным и запускается — отказ `noFreeAccount` перестал быть тупиком для игрока
      со своим аккаунтом.
- [ ] Офлайн (`isTransportOffline()`): отказ `games.houseAccountOfflineBody` поднимается **только** для
      режима «клубный». Режим «свой» офлайн запускается (`catalog.launchGame` намеренно вне
      `OFFLINE_BLOCKED`, C2.12).
- [ ] Быстрый запуск с карточки «Продолжить» решения не спрашивает: идёт клубным режимом, а на
      `noFreeAccount` открывает модал, где выбор уже виден.
- [ ] `pnpm design:verify` и `pnpm icons:verify` зелёные, модал не теряет обложку на 693px.

## 4. Как это уже сделано рядом (эталон)

Развилка «строка чеклиста есть / нет» уже написана в `hooks/use-game-launch.ts` — новый режим встраивается
в неё, а не рядом с ней:

```ts
// hooks/use-game-launch.ts — как сейчас
steps: state.needsAccount
  ? LAUNCH_STEPS
  : LAUNCH_STEPS.filter((id) => id !== 'account'),
```

То есть в `LaunchState.needsAccount` теперь пишется `game.needsHouseAccount && mode === 'house'`, и строка
«Выдача аккаунта» исчезает для своего аккаунта тем же механизмом, каким она уже исчезает для Steam-игры.
Ни одной новой ветки в рендере чеклиста.

Grant и релиз тоже уже стоят в правильных местах — их достаточно сузить одним условием:

```ts
const needsGrant = game.needsHouseAccount && mode === 'house'

if (needsGrant && isTransportOffline()) {   // было: game.needsHouseAccount
  toast('error', t('games.houseAccountOfflineBody'))
  return
}
// ...
if (needsGrant) {                            // было: game.needsHouseAccount
  grant = await grantHouseAccount(game.id)
  // ...
}
```

Радио-группа: эталон разметки — существующая некликабельная строка пула в
`game-launch-modal.tsx` (`well-shallow`, диск состояния + текст справа). Из неё делается
`<fieldset>` + два `<label><input type="radio" className="sr-only">`, потому что нативный `input`
даёт стрелки и озвучивание бесплатно, а headless-кнопки с `role="radio"` пришлось бы озвучивать руками.
Один неон в диалоге принадлежит «ЗАПУСТИТЬ» (§3.3) — выбранный режим подсвечивается **рамкой**
(`border-primary`), не заливкой и не свечением.

## 5. Данные и текст

**Мок-API.**
- `fetchHouseAccounts()` начинает фильтровать: отдаёт только строки, которые клуб вправе лендить, то есть
  ровно то, что уже проверяет приватный `isGrantable` в `lib/mock/api/catalog.ts`. Отдельный флаг
  `grantable` в тип не добавляем: правило «строку с `linkedUser` не выдаём» уже живёт в одном месте на
  сервере, и второй его экземпляр в контракте разошёлся бы с первым.
- Новый `fetchPersonalAccountLink(): Promise<string | null>` — метка привязанного личного логина
  (`db.houseAccounts` строка `personal`, `linkedUser: 'demo_player_steam'`), только для подписи на карточке.
  Ключ `useApi`: `catalog/personal-link`, префикс `catalog` уже инвалидируется целиком.
- Ключи `useApi` в модале: существующий `catalog/house-accounts` (теперь короче на одну строку) плюс
  `catalog/personal-link`. `EVENT_INVALIDATES` не правим — оба чтения под префиксом `catalog`.
- Счётчик считается на клиенте из полученных строк (`status === 'available'` против `'in-use'`), потому что
  это арифметика по уже пришедшему списку, а не новое знание о клубе. Отдельный эндпоинт-счётчик дал бы
  два источника одного числа, способные разойтись между запросами.

**Типы.**
- `lib/types/catalog.ts`: `export type HouseAccountMode = 'house' | 'personal'`.
- `lib/agent/bridge.ts`: `LaunchGameOptions.accountMode?: HouseAccountMode`. Отдельное поле, а не
  «`houseAccountId` пустой ⇒ логинится сам»: у Steam-игры `houseAccountId` пустой всегда, и агент, который
  выводил бы режим из отсутствия id, для такой игры честно не отличал бы «клубного логина не требуется» от
  «игрок войдёт руками».
- `GameLaunchProgress.step` — открытый `string` по контракту, поэтому `awaitingPlayerLogin` не расширяет
  ни один union; его нужно только добавить в `STEP_GROUP` хука со значением `'launcher'`.

**Новые ключи i18n (все три словаря `en` / `ru` / `lt`):**

| Ключ | Смысл |
|---|---|
| `games.accountModeTitle` | заголовок группы, вместо `games.selectAccount` («Вход в игру») |
| `games.accountModeHouse` | «Клубный аккаунт» |
| `games.accountModeHouseBody` | «Клуб сам выдаст свободный логин на время сессии» |
| `games.accountModeHousePool` | счётчик: `{free} свободно · {busy} занято` |
| `games.accountModeHouseEmpty` | состояние «свободных нет» на карточке клубного режима |
| `games.accountModePersonal` | «Свой аккаунт» |
| `games.accountModePersonalBody` | «Откроем чистый лаунчер — войдёшь под своим логином» |
| `games.accountModePersonalLinked` | подпись с привязанным логином: `Привязан: {name}` |

`games.selectAccount` удаляем из трёх словарей — после правки его никто не читает; `games.accountLinked`
остаётся (его использует `accountModePersonalLinked`-подпись, если решишь переиспользовать — тогда новый
ключ не заводи). `games.accountAvailable` / `accountInUse` остаются: их читает счётчик.

## 6. Подводные камни

- **Высота модала.** Карточка уже самая высокая в продукте: обложка 160px + контент + футер под
  `OVERLAY_MAX_H`. Две карточки режима **дешевле** прежнего списка из четырёх строк, но только если счётчик
  остаётся строкой внутри карточки клубного режима, а не отдельным блоком над группой. Проверять на 693px:
  обложка не должна уезжать.
- **Пул пуст, но выбран «свой».** Панель очереди рисуется по `accountBusyId === launchGameId`. При
  переключении на «свой» она не должна перекрывать выбор: панель показывается, только пока выбран клубный
  режим. Сам `accountBusyGameId` при переключении **не чистим** — это ответ сервера, и он снова верен, если
  игрок вернётся к клубному режиму.
- **Релиз.** Единственное место, где grant возвращается (`catch` в `launch`), уже условно по `grant !== null`
  — при режиме «свой» `grant` остаётся `null`, и трогать эту ветку не надо. Если сузишь её ещё и по `mode`,
  появится второй способ ответить на один вопрос.
- **Офлайн.** Сузить надо именно проверку `isTransportOffline()`, а не убрать: клубный режим офлайн
  по-прежнему обязан отказать **до** чеклиста, иначе игрок смотрит старт, который не может закончиться.
- **Гостевая поверхность.** Модал запуска — за авторизацией, гостю он не показывается; новых гостевых
  состояний пункт не создаёт.
- **Долг от C4.1.** Обложки в модале всё ещё градиентные — на скриншотах проверки это ожидаемо, чинит C4.1.

## 7. Проверка

```
pnpm design:verify
pnpm icons:verify
pnpm tsc --noEmit
```

Браузер (1920×1080 и 1366×768), игра с `needsHouseAccount: true`:

1. Открыть модал: две карточки, выбран клубный, счётчик совпадает с числом строк пула, в списке нет
   `Personal Steam Account`.
2. Запуск клубным режимом: строка «Выдача аккаунта» на месте, после старта — строка с меткой аккаунта.
3. Переключить на «свой», запустить: строки «Выдача аккаунта» нет, метки аккаунта нет, запуск доходит до
   «Игра запущена», в пуле ни одна строка не стала `Занят`.
4. `?fail=catalog.grantHouseAccount:noFreeAccount`: клубный режим → тост + панель очереди; переключение на
   «свой» → запуск проходит.
5. Офлайн-переключатель `/dev/kit`: клубный режим отказывает текстом пула, «свой» запускается.
6. Клавиатура: `Tab` в группу, стрелки переключают режим, `Enter` на «ЗАПУСТИТЬ» стартует выбранный.
