## 1. Что нужно сделать

Дословно из плана:

> **C4.11** Режим запуска: **личный** аккаунт или **клубный**. Две плитки-радио в модале запуска для
> игр с `needsHouseAccount: true`; личный режим не запрашивает грант вообще (чеклист из трёх строк,
> «чистый» лаунчер), клубный работает как сейчас (сервер выдаёт свободную строку). На клубной плитке —
> живые счётчики «N свободно · M занято», ряд `linkedUser` уезжает из списка пула на личную плитку.

Зачем: сегодня игра с `needsHouseAccount` **всегда** идёт через клубный пул, даже если игрок пришёл
со своим Steam. Он получает чужой логин, чужую библиотеку и чужой ранг — и обходит это только тем,
что не запускает игру из лаунчера вовсе.

## 4. Как это сделать (принятые решения)

**Одна производная в хуке, а не четыре проверки.** Ветка обязана считаться один раз, иначе личный
запуск офлайн упрётся в гейт выдачи, которой он не просил:

```ts
const launch = useCallback(
  async (game: { id: string; name: string; needsHouseAccount: boolean }, mode: LaunchAccountMode = 'club') => {
    /**
     * Единственный источник ветки. `game.needsHouseAccount` отвечает на «умеет ли
     * титул клубный логин», а не на «нужен ли он этому запуску»: со своим Steam
     * игрок не просит у клуба ничего, и гейты выдачи к нему не относятся.
     */
    const needsAccount = game.needsHouseAccount && mode === 'club'

    if (needsAccount && isTransportOffline()) { /* games.houseAccountOffline* — как было */ }
    setState({ ...IDLE, needsAccount })
    …
    if (needsAccount) grant = await grantHouseAccount(game.id)
    …
    agent.launchGame(game.id, { onProgress, signal, houseAccountId: grant?.accountId })
```

`steps` наружу уже считается от `state.needsAccount` — там не меняется ни строки, три строки чеклиста
получаются бесплатно.

**Плитки — `radiogroup`, а не две кнопки.** Роль `radiogroup` на контейнере, `role="radio"` +
`aria-checked` на плитках, стрелки внутри группы, `Tab` — из неё; в группе один tab-stop (паттерн
`useRovingFocus`, как у чипов фильтров `C4.2`). Дизайн: `rounded-lg border border-border well-shallow`,
выбранная — `border-primary` + мягкое свечение `primary`; **T1-неона на плитках нет** — единственный
T1 кадра принадлежит кнопке «Запустить» (§4.2, иначе падает `design:verify` R3). `tick-corners` не
дублируем. Счётчики — `label-mono`, мелкий кегль.

**Счётчики — из того же чтения, что и пул.** `fetchHouseAccounts()` под уже существующим ключом
`catalog/house-accounts` (второго запроса не заводим), считается в `useMemo`:

```ts
const club = accounts?.filter((a) => !a.linkedUser) ?? []
const free = club.filter((a) => a.status === 'available').length
const busy = club.filter((a) => a.status === 'in-use').length
const personal = accounts?.find((a) => a.linkedUser)
```

`free === 0` → плитка печатает `games.accountModeClubNone` и остаётся выбираемой: «Запустить» отдаёт
отказ `noFreeAccount`, а его уже ловит панель очереди. Своей проверки «не давать нажать» не пишем —
свободная строка могла освободиться между рендером и нажатием, и решает это сервер.

**Пул под плитками.** Тот же блок, что сейчас, но `accounts.filter((a) => !a.linkedUser)`: personal-ряд
теперь живёт подписью на личной плитке (`games.accountModePersonalLinked` с `{name: personal.linkedUser}`),
и печатать его дважды значит предлагать то, чего грант никогда не выдаст.

**Сброс стейта.** `mode` сбрасывается в `'club'` в том же эффекте, где модал реагирует на смену
`launchGameId`: режим, унаследованный от предыдущей игры — это молчаливый выбор за игрока.

## 5. Данные и текст

Типов данных не добавляется — только режим:

```ts
/**
 * Чем игрок входит в титул, который умеет клубный логин (C4.11).
 *
 * Это выбор *режима*, а не строки пула: какой именно логин свободен, решает клуб
 * (`catalog.grantHouseAccount` принимает только `gameId`). `'personal'` означает
 * «клуб не участвует» — гранта нет, и лаунчер открывается чистым.
 */
export type LaunchAccountMode = 'personal' | 'club'
```

## 6. Подводные камни

- **Гейт офлайна.** Если оставить `game.needsHouseAccount` в проверке `isTransportOffline()`, личный
  запуск без связи с клубом откажет копией про клубный аккаунт — самый вероятный баг этого пункта.
- **`design:verify` R3.** Свечение выбранной плитки делать рамкой и `shadow`, а не вторым
  `neon-ring` / `neon-edge`: два T1 в файле = падение скрипта.
- **`bg-black` и hex.** Плитки собираем из `well-shallow` / `border-border` / токенов; `bg-black/NN`
  в JSX = падение R2.
- **Идемпотентность гранта не ломается.** Игрок, запустивший титул клубно, а потом лично, остаётся с
  уже выданной строкой: личный режим её **не освобождает** — освобождение живёт в двух местах
  (`catch` хука и «Игра закрыта» в `in-game-strip.tsx`), третьего не заводим.
- **Иконки** — только `lib/icons.ts` (`icons.community` для клубной, `icons.profile`/`icons.user` для
  личной — взять существующий ключ, новых глифов не добавлять), эмодзи запрещены.

Браузер, 1920×1080 и 1366×768, демо-режим, ru + ещё один язык:

1. Игра с общим аккаунтом → две плитки, клубная выбрана, счётчики совпадают со списком пула ниже,
   personal-ряда в списке нет.
2. Клубный запуск → чеклист **четыре** строки, «Аккаунт IMBA_0X закреплён за тобой», полоса «В игре»
   печатает ту же строку.
3. Личный запуск → чеклист **три** строки, строки закрепления нет ни в диалоге, ни в полосе, пул не
   изменился.
4. Игра без общего аккаунта → плиток нет, диалог как раньше.
5. Офлайн (`/dev/bus` → транспорт) → клубный отказывает копией про офлайн-выдачу, личный
   **запускается**.
6. Все клубные заняты → плитка говорит «нет свободных», «Запустить» открывает панель очереди.
7. Клавиатура: стрелки переключают плитки, `Tab` уходит на «Запустить», фокус видим.
